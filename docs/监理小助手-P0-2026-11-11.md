# 监理小助手 P0（全站悬浮球）— 2026-11-11

## 做了什么

在 web-admin 布局层挂了一个全站悬浮球，接后端已有 Agent（`/api/agent/chat`），
不另起对话引擎。P0 范围：对话、结果卡、页面动作、历史会话、快捷键。

- 悬浮球固定在右下角；点击展开 384px 面板；`Ctrl/⌘ + K` 唤起，`Esc` 收起
- 空状态给四条例句（打开台账 / 今天的记录有几条 / 生成今天的监理日志 / 未整改的隐患）
- 助手回执渲染：纯文字（pre-wrap）、结果列表行、链式动作、撤销、chips、图表卡（预留）
- 页面动作：后端 `navigate` 返回的小程序路径（`/pages/...`）在前端映射成 web 路由
- 历史会话：面板内切换，按 user + project 隔离；切项目自动开新会话
- 视觉约束：无蓝/紫/渐变，无阴影、无大横幅、无表情，卡片全部做成列表行 + 细分割线

## 踩过的坑

1. **Rolldown 分块**：图表组件若被静态 import 进布局层，`rolldown-runtime` chunk 会消失，
   入口初始化顺序错乱 → 全站白屏（`TypeError: e is not a function`）。
   改为 `defineAsyncComponent(() => import('./AssistantChart.vue'))` 后恢复。
2. **bind mount**：见上，dist 目录只可原地覆盖。
3. **nginx 容器重建**：官方镜像 entrypoint 的 `apk manifest` 在本机会卡住，
   容器重建后 nginx 不启动；`pkill -9 apk` 后可正常拉
   （重建还会丢 `docker cp` 进去的 `/lab/`，已从 `/home/baize/jl-field-test` 恢复，
   并留了主机副本 `/home/baize/rokid_glass/lab`）。
4. **conversation_id 必传**：后端 `conversation_id` 缺省为 `None` 时不落展示历史，
   Web 端每次请求都带客户端生成的 id，历史才可用。

## P0.6 流式思考 + 流式回答（同日继续）

### 后端

- `app/services/model_gateway.py` 新增 `stream_chat_completion()`：解析供应商 SSE，
  分字段产出 `reasoning`（`delta.reasoning_content`）/ `content`（`delta.content`），
  支持 `enable_thinking=false` 关闭思考
- `app/routers/agent.py` 新增 `POST /api/agent/chat/stream`（SSE）：
  `meta` / `progress` / `reasoning` / `answer` / `done` / `error`；
  `done` 里是与 `/chat` 完全一致的完整回执（cards/actions/undo/need_more…）。
  **不改现有 `/chat`**，两条路并存
- 流式实现方式：`ContextVar` 注入 emitter（避免改 600 行 `_agent_chat_impl` 签名）；
  emitter 存在时 `_plain_answer` 走流式模型、路由模型 `enable_thinking=false`。
  路由模型的 content 是 JSON 规划，**不展示**；思考过程只来自「回答模型」
- 踩坑：这台机器 fastapi 0.140 不再从顶层导出 `StreamingResponse`，
  改从 `starlette.responses` 导入（否则整个后端 import 失败）

### 前端

- `chatStream()`：fetch + ReadableStream 解析 SSE（EventSource 不能 POST / 带 Authorization）
- 新增 `AssistantReasoning.vue`：
  - 灰色 `<pre>` 纯文本，不做 Markdown；最大高度 200px、内部滚动
  - 标题：`思考中… Ns`（每秒跳）→ `已深度思考（N 秒）`；工具轮显示 `处理过程（N 秒）`
  - 答案开始输出 / 本轮结束时自动收起，用户手动展开过则尊重用户
  - 自动跟随：离底部 < 28px 才跟随；用户上翻自动停止，滚回底部恢复
- 消息新增 `reasoning/steps/thinkingMs/answerStarted/streaming`；
  **流式消息必须 `reactive(...)`**（push 原始对象后再改不会触发重渲染，踩过）
- 降级：SSE 不可用 / 传输层失败且没收到任何增量 → 自动回退 `/api/agent/chat`

### 实测（生产，admin 账号）

| 场景 | 结果 |
|---|---|
| 纯问答 | 首条思考 3.9s、首条答案 10.3~11.7s、总 11~12.4s；reasoning 121~141 块、answer 12~13 块、done 1 |
| 工具轮（"打开台账"） | 无 reasoning，progress 5~7 条 + done，约 9s；渲染"处理过程（3 秒）"+ 动作链接 |
| 非流式 `/chat` 回归 | action 与纯问答两条都正常（小程序/H5 不受影响） |
| nginx 缓冲 | 直连 6081 与经 nginx 443 计时一致（`X-Accel-Buffering: no` 生效，不用改 nginx） |

### 已知限制

- 工具轮结果（卡片/动作）只能最后一次性给出，不是 token 级流式
- 思考内容不进历史库（只落最终答案），历史会话回看没有思考过程
- 路由阶段关掉思考是为了快 + 不泄漏内部 JSON 规划，所以只看到"回答模型"的思考
- 思考 token 计费；暂无"关闭思考"开关（P2）

## P0.7 文内引用 + 文末统一归纳（同日继续）

### 做法

- **统一结构**：agent 回执新增 `citations: [{index, kind, title, sub, snippet, target, ref_id}]`；
  正文里用 `[[n]]` 做行内标记
- **工具轮**：`_query_regulation` 返回 3 条规范引用，并在每条依据后标 `[[n]]`
- **问答轮**：新增 RAG 引用链路 `_retrieve_citations`（复用 rag_index 混合检索，
  覆盖知识库/文书/工作记录/笔记），把材料按编号拼进 system prompt，
  要求模型"用到哪条就标 [[n]]"，并把同一份材料清单写回 `citations`
- 非流式 `/chat` 复用路由 answer 时，只补引用列表（正文没有编号标记），不影响小程序

### 前端

- `AssistantAnswer.vue`：把 `[[n]]` 解析成可点击的小角标
- 点角标 / 文末条目 → 浮层（Teleport 到 body、fixed 定位、细边框无阴影）：
  显示来源类型、标题、片段，可「打开来源」跳到 `/knowledge-base`、`/documents`、
  `/work-record/inspection`、`/inspection-dashboard`
- 文末统一「引用 · N 条」列表：编号 + 标题 + 来源类型；Esc / 点空白关闭
- 引用数据随 `done` 事件一起到，流式输出过程中角标先显示编号，完成后可点开来源

### 实测

| 场景 | 结果 |
|---|---|
| 问答（旁站监理） | 5 条引用、正文 2 个行内角标；点开浮层显示"实施旁站"实体说明 |
| 规范查询（模板支撑验收） | 3 条引用、正文 3 个角标；点文末条目 → 浮层 →「打开来源」跳到 `/knowledge-base` |
| 控制台 | 0 报错 |

### 已知边界

- 目前引用覆盖：**问答（RAG）+ 规范查询**；文书/记录/隐患列表仍用结果卡（本身可点）
- 出稿类"依据清单"（记录/照片/规范/记忆）尚未接入悬浮球，是小程序已有的能力，后续可补
- RAG 偶尔会召回泛化标题（如"监理"），后续按片段长度/来源类型再过滤

## P0.8 思考过程随历史会话还原（同日继续）

### 问题

- 思考过程只存在于 SSE 流里，历史会话只落「最终文本」→ 重新打开历史 / 刷新页后
  「已深度思考」整块消失
- 点「新会话」后当前面板清空，用户以为内容没了（其实旧会话在「历史会话」里，
  但进去只剩文本，思考与引用都没了）

### 修复

- 后端：流式轮次用 `_STREAM_META`（ContextVar）收集 reasoning（最多 12000 字）、
  progress 步骤（最多 12 条）、首条答案到达耗时；在保存展示历史前
  `_attach_stream_meta(result)` 附到回执上——`append_conversation_response` 本来
  就整份 response 入库，因此思考/步骤/耗时/引用一起持久化
- 前端：`messageFromStored()` 从历史消息的 `response` 里还原
  `reasoning / steps / thinking_ms / citations`；还原后思考区默认收起，
  点「展开」能看原文
- 旧会话没存思考：标签退化为「已深度思考」不带秒数，不编造耗时

### 实测

| 操作 | 结果 |
|---|---|
| 发问 → 新会话 → 历史 → 点回旧会话 | 「已深度思考（11 秒）」+ 思考原文 627 字 + 5 条引用 + 2 个行内角标 |
| 刷新页面 → 点开悬浮球 | 同上，自动恢复 |
| 控制台 | 0 报错 |
