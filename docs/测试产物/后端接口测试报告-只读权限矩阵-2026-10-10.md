# 后端接口测试报告（只读权限矩阵）

**测试日期**：2026-10-10
**目标环境**：生产 `https://www.baize.gdces.cn`
**脚本**：`docs/测试产物/_export_api.py`（接口盘点）、`_perm_matrix_readonly.py`（只读权限矩阵）
**原始数据**：`_api_inventory.json`、`_perm_matrix.csv`

## 一、接口盘点

| 指标 | 数量 |
|---|---|

> 见下。

## 二、未登录访问测试（anonymous，6 身份之一）

**结论：111 个只读接口中，仅 2 个未登录可访问，均属设计内。**

| 接口 | 状态 | 判定 |
|---|---|---|
| `GET /api/auth/roles` | 200 | ✅ **设计内**。登录页需在鉴权前拉取可选岗位列表；仅返回角色 key/中文名，无敏感数据 |
| `GET /api/auth/invite-codes/validate?code=` | 422 | ✅ **设计内**。注册前校验邀请码可用性必须免登录；422 仅因测试未带 `code` 参数（实际带参时按码是否有效返回） |

> 其余 109 个只读接口未登录一律 **401**，门控正常。

## 三、低权限越权读测试（inspector，最低业务岗）

脚本初筛出 14 条「低权限拿到 200 且模块声明了权限」的**候选**，逐条回源码复核后：

**结论：14 条全部为误报，无真实越权。**

误报根因：`declared_perm` 取自 OpenAPI 里**该路由模块**的权限声明，而同一 router 内
**GET 端点用 `get_current_user`（仅要求登录）、POST/PUT/DELETE 才用 `require_permission`**。
脚本按模块匹配，故把「写接口的权限」错误地套到了「读接口」上。

逐条复核结果：

| 接口 | 端点实际依赖 | 判定 |
|---|---|---|
| `GET /api/acceptance-templates` | `get_current_user`（`acceptance_template` 权限只在 POST/PUT/DELETE） | ✅ 登录即可读，设计内 |
| `GET /api/acceptance-templates/types` | `get_current_user` | ✅ 同上 |
| `GET /api/inspection/active` · `/stats` · `/trend` · `/category-distribution` · `/recent` · `/history` | `require_permission("inspection")` | ✅ **inspector 本就持有 `inspection`**，非越权 |
| `GET /api/knowledge/regulations/versions` · `/{filename}` | `get_current_user`（`settings` 只在 POST 版本管理） | ✅ 登录即可读 |
| `GET /api/kg/stats` | `knowledge_base`（inspector 持有） | ✅ 非越权 |
| `GET /api/omni/status` | `require_permission("local_ai")` | ⚠️ **待复核**：inspector 能拿到 200，需确认 `local_ai` 是否应开放给监理员（本地语音/AI 状态查询，倾向属正常业务能力） |
| `GET /api/project/list` | `get_current_user`（`project_create` 只在 POST /create） | ✅ 登录即可看项目列表，设计内 |
| `GET /api/task/notifications` | `get_current_user`（`task_receive` 在 POST respond） | ✅ 自己的通知，设计内 |

## 四、权限边界正例（符合设计的关键断言）

| 接口 | inspector | chief（总监） | admin（超管） | 设计预期 |
|---|---|---|---|---|
| `GET /api/project/{id}/members` | **403** | 200 | 200 | 成员管理限 `member_manage`（总监+超管）✅ |
| `GET /api/task/company` | **403** | 200 | 200 | 公司级任务视图限管理层 ✅ |
| `GET /api/task/assignable-users` | **403** | 200 | 200 | 派活需 `task_assign` ✅ |
| `GET /api/task/assigned-by-me` | **403** | 200 | 200 | 同上 ✅ |
| `POST /api/project/create` | **403** | **403** | 200 | 立项仅超管（`project_create`）✅ |

> 注：`POST /project/create` 的越权缺陷已于本日修复（原仅要求登录，监理员可立项）——
> 上表为修复后实测。

## 五、结论与待办

1. ✅ **未登录门控正常**：仅 2 个设计内公开接口。
2. ✅ **无低权限越权读**：14 条初筛全部为脚本误报，回源码复核无一成立。
3. ✅ **权限边界符合设计**：成员管理、公司任务、派活、立项均按预期拦截。
4. 🔸 **1 项待复核（非阻断）**：`GET /api/omni/status` 对 inspector 开放，需确认
   `local_ai` 权限是否应下放（当前不影响功能，属产品口径问题）。
5. 🔸 **附带发现**：`projects` 表存在 id=4/id=5 两个无成员的测试残留项目
   （「自动化测试项目%05d」），建议清理（待用户确认）。

**覆盖范围说明**：本轮按用户要求**只跑只读接口**，未对 193 个写接口做权限矩阵测试
（避免污染生产数据）。如需完整覆盖，建议在独立测试环境执行。
