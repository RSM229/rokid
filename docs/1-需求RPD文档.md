## 1. 系统概述

### 1.1 系统定位

本系统面向建筑工程监理行业，为现场监理人员提供一套覆盖"记录-识别-文书-台账-协同"全流程的智能辅助工具。系统支持 **AI 眼镜端（现场零手持作业端）、手机浏览器端（便携经办端）、微信小程序端（微信生态移动协作端）、PC Web 管理端（后台管控归档端）** 四端协同工作，核心目标是将监理日常工作数字化、智能化，减少手工填表工作量，提升现场监管效率。

### 2.3 登录规则

- 用户登录时需选择角色（总监理工程师 / 总监代表 / 专业监理工程师 / 监理员）
- Web 端开放客户自助注册，默认注册为“监理员”，注册后可直接登录
- 自助注册账号不允许自行绑定项目，也不能自行申请总监等高权限角色；项目绑定和角色提升由总监/系统管理员在“用户管理”中完成
- 自助注册角色由服务端 `PUBLIC_REGISTRATION_ROLES` 白名单控制，登录角色必须与账号角色一致
- `admin` 超级管理员账号可任意角色登录，拥有全部权限
- 被禁用的账号无法登录

## 3. 工作台

### 3.1 功能说明

工作台是用户登录后的首页，集成了智能监理助手和工作统计概览。

### 3.2 智能监理助手

- **对话框形式**：用户通过文字或语音输入指令，系统返回回复或执行跳转
- **指令路由**：系统内置指令匹配表，支持以下自然语言指令：

| 指令示例 | 系统行为 |
|---|---|
| "工作记录" / "打开工作记录" | 进入工作记录层级 |
| "巡视记录" / "巡视" | 跳转巡视记录页面 |
| "验收记录" / "验收" | 跳转验收记录页面 |
| "旁站记录" / "旁站" | 跳转旁站记录页面 |
| "见证记录" / "见证" | 跳转见证记录页面 |
| "新建巡视记录" | 跳转巡视记录新建页面 |
| "新建验收记录" | 跳转验收记录新建页面 |
| "启动隐患识别" | 在工作台对话中进入隐患识别模式，提示导入现场图片 |
| "现场识别" | 跳转现场识别页面 |
| "拍照" | 跳转现场识别页面 |
| "生成监理日志" | 弹出监理日志生成对话框 |
| "查看台账" | 跳转台账管理页面 |
| "知识库" | 跳转信息库页面 |
| "返回" / "主页" | 返回主页 |

- **图片识别**：用户可在工作台导入现场图片，配合自然语言指令（如"识别一下这张图的隐患"），系统将图片和指令一起发送给 AI，结果直接显示在当前对话
- **模型选择**：用户可在底部工具栏选择使用的 LLM 模型
- **知识库选择**：用户可选择关联的知识范围（全部 / 省统表 / 安全监理用表 / 知识图谱）；“全部”同时检索整个知识文档库和知识图谱
- **未匹配指令**：当输入的指令不在路由表中时，系统调用 LLM 进行自由问答

### 3.3 工作统计概览

- 在工作台底部展示各类工作记录的"未查看"和"未处理"数量
- 统计范围按项目维度，覆盖：巡视、验收、旁站、见证、其他工作
- 展示安全隐患待处理数量
- 点击统计卡片可跳转到对应记录列表

### 3.4 层级导航

- 面包屑导航显示当前所处层级（如"工作记录 > 验收记录 > 新建"）
- 用户通过指令或点击操作逐级进入

### 3.5 实现状态

- ✅ 眼镜端 MenuActivity 主菜单（9 项入口 + 语音选择）

## 4. 工作记录管理

### 4.1 记录类型

系统支持四种监理工作记录，每种记录有独立的表单字段和工作流程：

| 类型 | 业务场景 | 核心字段 |
|---|---|---|
| **巡视记录** | 日常现场巡视检查 | 施工区域、位置、施工内容、天气、巡视备注、巡视照片（带水印） |
| **验收记录** | 工程质量验收 | 验收类型、施工区域、位置、验收内容、验收指引引用、验收结果（合格/不合格/待整改）、自动生成省统表文书 |
| **旁站记录** | 关键工序旁站监督 | 旁站工程名称、旁站部位、开始/结束时间、旁站情况描述、旁站结论 |
| **见证记录** | 见证取样送检 | 材料名称、规格型号、施工区域、位置、见证照片 |

### 4.2 记录状态流转

```
草稿 -> 已提交 -> 已审批 -> 已归档
                ↓
             已驳回
```

- **草稿**：新建后的初始状态，可编辑修改
- **已提交**：提交后等待审批
- **已审批**：审批通过
- **已驳回**：审批不通过，退回修改
- **已归档**：最终归档状态

### 4.3 巡视记录

#### 4.3.1 业务流程

1. 监理人员进入施工现场
2. 新建巡视记录，填写施工区域、位置、施工内容、天气
3. 现场拍照（照片自动添加水印：项目名称、单位工程、施工区域、施工内容、拍摄时间、天气）
4. 可补充巡视备注
5. 提交巡视记录

#### 4.3.2 照片水印要求

巡视照片必须包含以下水印信息：
- 项目名称
- 单位工程
- 施工区域
- 施工内容
- 拍摄时间（精确到秒）
- 天气

### 4.4 验收记录

#### 4.4.1 业务流程

1. 选择验收类型（如钢筋验收、混凝土验收、模板验收等）
2. 系统根据验收类型从知识图谱中获取验收指引（步骤、要点、常见违规、规范依据）
3. 填写施工区域、位置、验收内容
4. 系统自动生成省统表验收记录文书
5. 记录验收结果（合格 / 不合格 / 待整改）

#### 4.4.2 验收指引内容

每种验收类型包含以下指引信息：
- **验收步骤**：如钢筋验收包含"材料进场验收 -> 钢筋加工检查 -> 钢筋连接检查 -> 钢筋安装检查 -> 隐蔽工程验收"
- **检查要点**：如"钢筋型号规格、间距、保护层厚度、搭接长度、锚固长度"
- **常见违规**：如"钢筋型号不符、间距偏差超标、保护层不足、搭接长度不够"
- **规范依据**：如"GB 50204 混凝土结构工程施工质量验收规范"

### 4.5 旁站记录

#### 4.5.1 业务流程

1. 新建旁站记录，填写旁站工程名称、旁站部位
2. 系统自动记录开始时间
3. 旁站过程中填写旁站情况描述
4. 旁站结束时填写旁站结论
5. 系统自动记录结束时间并提交

### 4.6 见证记录

#### 4.6.1 业务流程

1. 新建见证记录，填写材料名称、规格型号、施工区域、位置
2. 拍照记录取样过程（见证照片）
3. 提交见证记录

### 4.7 通用操作

- **查看列表**：按记录类型、状态筛选查看
- **查看详情**：查看记录完整信息
- **编辑**：仅草稿状态可编辑
- **提交**：草稿状态可提交
- **标记已查看**：将记录标记为已查看，影响工作台统计
- **统计**：按项目维度统计未查看和未处理数量

- ✅ 后端 WorkRecord 模型增加 `reject_reason` / `approved_by` / `approved_at` 字段

## 5. 安全隐患识别与整改闭环

### 5.1 业务场景

监理人员在现场发现安全隐患时，拍照上传，系统通过 AI 视觉模型自动识别隐患类型和风险等级，生成隐患记录和整改通知单，跟踪整改过程直到闭环。同时支持**云端 AI 实时巡检**模式：眼镜端按频率自动采集画面并上传云端，大模型实时识别，识别到隐患立即语音提醒+震动+自动取证+联动整改（详见第 15 章）。

### 5.2 隐患识别

#### 5.2.1 识别方式

- **拍照识别**：通过 AI 眼镜端、手机浏览器端、微信小程序端或 Web 管理端上传照片
- **自然语言辅助**：用户可附加自然语言指令（如"重点检查脚手架"），AI 结合指令进行识别
- **批量识别**：现场识别页面支持多张图片批量识别
- **AI 自动巡检**：眼镜端通过"启动安全AI巡检/停止安全AI巡检"语音指令启停自动巡检，按频率采集画面自动识别

#### 5.2.2 可识别隐患类型

| 大类 | 典型隐患 |
|---|---|
| **人员违章** | 未戴安全帽、未系安全带、违规吸烟、违规高处作业等 |
| **设施隐患** | 临边防护缺失、脚手架搭设违规、临时用电违规、机械设备异常等 |
| **环境隐患** | 物料乱堆乱放、消防设施缺失、通道堵塞、扬尘超标等 |

#### 5.2.3 AI 识别返回结果

| 字段 | 说明 |
|---|---|
| 风险状态 | 存在隐患 / 无隐患 |
| 风险类别 | 安全帽、临边防护、脚手架、临时用电、机械设备等 |
| 主要风险 | 隐患描述（如"施工人员未佩戴安全帽"） |
| 证据 | 识别到的证据列表 |
| 不确定性 | 低 / 中 / 高（反映识别置信度） |
| 复查建议 | 建议的复查事项列表 |
| 场景关联 | 场景类型描述 |

### 5.3 隐患记录管理

#### 5.3.1 隐患状态流转

```
已提报 -> 已通知整改 -> 整改中 -> 待复查 -> 已闭环
                                    ↓
                               驳回整改
```

| 状态 | 说明 |
|---|---|
| **已提报** | AI 识别后自动创建，尚未通知 |
| **已通知整改** | 已生成整改通知单并通知施工单位 |
| **整改中** | 施工单位正在整改 |
| **待复查** | 施工单位提交整改后影像，等待监理复查 |
| **已闭环** | 监理复查通过，隐患处理完成 |
| **驳回整改** | 监理复查不通过，要求重新整改 |

#### 5.3.2 隐患记录字段

- AI 识别结果（风险状态、类别、主要风险、证据、复查建议等）
- 关联影像（隐患照片路径、整改后照片路径）
- 关联文书（整改通知单 ID）
- 位置信息（施工区域、具体位置）
- 备注
- 创建时间、更新时间

### 5.4 整改闭环流程

```
1. AI 识别隐患 或 现场语音提报 -> 自动创建隐患记录（状态：已提报）
2. 监理语音一键开具整改通知单 -> 生成安全隐患整改通知单（状态：已通知整改）
3. 整改通知单自动推送施工单位
4. 施工单位整改 -> 提交整改后影像（状态：待复查）
5. 监理语音触发复查，语音确认"复查合格/驳回整改"：
   - 通过 -> 隐患闭环（状态：已闭环）
   - 不通过 -> 驳回整改（状态：驳回整改）-> 返回整改
6. 整改全流程自动记入台账，可查询、可导出、可追溯
```

整改闭环关键能力：
- **语音一键开具**：现场拍摄或 AI 自动识别隐患后，监理可通过语音直接生成整改通知单
- **自动推送**：整改通知单自动推送至施工单位，无需手动转发
- **语音复查**：监理通过语音触发复查，并语音确认"复查合格/驳回整改"
- **台账联动**：整改全流程自动记入整改通知单台账与 AI 安全巡检台账

### 5.5 安全隐患整改通知单

- 根据隐患自动生成，包含：隐患描述、证据、复查建议、施工区域、位置、隐患照片、监理人员、整改期限
- 整改通知单需总监签发
- 可导出 PDF

## 7. 监理文书管理

### 7.1 文书类型

系统支持 8 类监理文书的生成和管理：

| 文书类型 | 说明 | 是否需要总监签发 |
|---|---|:---:|
| 旁站记录 | 旁站工作记录文书 | 否 |
| 监理日志 | 每日监理工作汇总 | 否 |
| 监理工程师通知单（质量类） | 质量问题通知 | 否 |
| 安全隐患整改通知单 | 隐患整改通知 | 是 |
| 巡视记录 | 巡视工作记录文书 | 否 |
| 验收记录 | 验收工作记录文书 | 否 |
| 见证取样记录 | 见证取样工作记录 | 否 |
| 监理周报 | 周度工作汇总 | 是 |
| 监理月报 | 月度工作汇总 | 是 |

### 7.2 文书状态流转与审批规则

```
草稿 -> 待审批 -> 已审批 -> 已归档
          ↓
       已驳回
```

- **草稿**：新建后的初始状态，可编辑
- **待审批**：提交审批后（仅需签发文书类型）
- **已审批**：总监审批通过
- **已驳回**：总监驳回
- **已归档**：直接归档（不需要签发的文书类型提交后直接归档）

#### 审批规则

- **专监生成普通文书直接归档**：旁站记录、监理日志、监理工程师通知单（质量类）、巡视记录、验收记录、见证取样记录等普通文书由专监生成后直接归档
- **总监签发文书需审批**：安全隐患整改通知单、监理周报、监理月报需总监签发，提交后进入审批流程
- **审批结果全端同步**：审批通过/驳回结果同步至眼镜端、手机浏览器端、微信小程序端、PC 端，全端可见

### 7.3 文书生成方式

#### 7.3.1 自动填充规则

所有文书生成时，系统自动调取对应影像、时间、部位、人员等数据，填充全部基础必填字段：

| 自动填充字段 | 数据来源 |
|---|---|
| 文书编号 | 系统自动生成（按文书类型编号规则） |
| 日期/时间 | 服务端时间 |
| 监理人员 | 当前登录用户姓名 |
| 监理级别 | 当前登录用户角色 |
| 施工区域/位置 | 关联工作记录或现场选择 |
| 天气 | 和风天气 API 自动获取 |
| 关联影像 | 自动调取对应工作记录或隐患的照片 |

#### 7.3.2 手动创建

- 用户选择文书类型，填写标题和内容
- 系统自动填充基础字段（见 7.3.1）

#### 7.3.3 LLM 智能生成

- 用户提供文书类型、标题、隐患信息（可选）、巡检信息、额外上下文
- 系统调用 LLM 自动生成文书正文内容
- 生成后创建文书草稿，用户可进一步编辑

#### 7.3.4 验收记录自动生成

- 创建验收记录时自动生成省统表验收记录文书
- 包含验收指引步骤、检查要点、常见违规、规范依据

#### 7.3.5 编辑规则

- **核心内容语音补充**：用户可通过语音口述补充文书核心内容，无需手动打字
- 支持简易修改，所有编辑保留版本记录

### 7.4 监理日志自动生成

#### 7.4.1 生成规则

选择日期后，系统自动聚合当日所有工作记录和安全隐患，按以下模块生成监理日志：

| 模块 | 内容来源 |
|---|---|
| **当日施工进展情况** | 汇总当日所有工作记录的施工内容 |
| **当日监理工作情况** | 分四小节：① 工程材料/构配件/设备进场报审及见证取样 -> 见证记录；② 旁站、巡视、平行检验 -> 巡视记录+旁站记录；③ 验收、工程实体抽测 -> 验收记录；④ 其他 -> 其他工作记录 |
| **当日存在问题及处理情况** | 安全隐患+质量问题，已闭环标记"已完成"，未闭环标记"已通知" |
| **其他有关事项** | 分五小节：会议、重要发文、闭合记录、资料上报、其他 |

#### 7.4.2 日志内容

- 项目名称、日期、星期
- 监理人员姓名和级别
- 天气信息
- 施工进展、监理工作、存在问题、其他事项

### 7.5 文书操作

- **创建**：手动创建或 LLM 生成
- **编辑**：仅草稿状态可编辑，支持语音补充内容
- **提交审批**：提交后进入审批流程
- **审批通过**：仅总监可操作
- **驳回**：仅总监可操作
- **导出 PDF**：生成标准 PDF 文件，**支持电子签名**，直接满足监理资料归档要求

## 10. 派单管理

### 10.1 业务场景

| 要素 | 说明 |
|---|---|

| 任务地点 | 任务执行的具体位置 |
| 施工区域 | 任务所属的施工区域 |

| 眼镜推送 | 是否同步推送到眼镜端 |

### 10.3 任务状态流转

```
待接单 -> 已接单 -> 进行中 -> 已完成
  ↓        ↓
已拒单   已取消（派单人取消）

进行中 -> 已取消（派单人取消）
待接单 -> 转派 -> 待接单（新被派人）
```

### 10.4 操作说明

| 操作 | 执行人 | 说明 |
|---|---|---|
| **派单** | 总监/总代 | 创建任务并指派给被派人 |
| **接单** | 被派人 | 确认接受任务 |
| **拒单** | 被派人 | 拒绝接受任务，需填写拒单原因 |
| **开始执行** | 被派人 | 标记任务开始执行 |
| **完成** | 被派人 | 标记任务完成，可填写完成备注和成果文件 |
| **转派** | 总监/总代 | 将任务转派给其他人 |
| **催办** | 总监/总代 | 向被派人发送催办通知 |
| **取消** | 总监/总代 | 取消任务 |

## 15. 云端AI安全隐患智能识别

### 15.1 整体逻辑

AI 眼镜端**不部署本地模型**，仅采集现场画面，通过云端 API 调用训练完成的工地安全隐患大模型，实现实时隐患识别。本能力是系统云端 AI 能力的核心，区别于本地 LLM 文本生成。

### 15.2 语音启停

仅通过以下语音指令控制 AI 巡检，无任何手动操作：

| 语音指令 | 行为 |
|---|---|
| "启动安全AI巡检" | 启动 AI 自动巡检模式 |
| "停止安全AI巡检" | 停止 AI 自动巡检模式 |

### 15.3 实时识别流程

```
眼镜端按频率采集现场高清图片
  ↓
实时上传云端 API
  ↓
大模型完成隐患识别
  ↓
结构化结果回传应用端（眼镜端/手机浏览器端/微信小程序端/PC端）
```

### 15.4 可识别隐患类型

| 大类 | 典型隐患 |
|---|---|
| **人员违章** | 未戴安全帽、未系安全带等 |
| **设施隐患** | 临边防护缺失、用电违规等 |
| **环境隐患** | 物料乱堆、消防缺失等 |

### 15.5 即时提醒

- 识别到隐患后，**眼镜端立即语音播报 + 震动提示**
- 同步推送至手机浏览器端和微信小程序端，确保监理人员第一时间感知

### 15.6 自动取证

- 识别隐患瞬间**自动抓拍照片**
- 照片自动叠加合规水印（项目/人员/时间/位置/天气/部位/隐患标识）
- 自动同步云端，进入影像台账

### 15.7 自动联动

- **自动匹配规范库条款**：识别到隐患后自动匹配对应规范条款，作为整改依据
- **语音一键生成整改通知单**：用户可通过语音确认生成整改通知单
- **全端同步流转**：整改通知单同步至眼镜端/手机浏览器端/微信小程序端/PC端，进入整改闭环流程（详见第 5 章）

### 15.8 离线兼容

- 无网络时**缓存现场画面**
- 联网后**自动上传补识别**，不丢失巡检数据

### 15.9 实现细节

**后端 API 路径**：
- `POST /api/inspection/start`：启动巡检会话（创建 `InspectionSession` 记录，返回 session_id）
- `POST /api/inspection/stop`：停止巡检会话（更新 session 结束时间与统计）
- `GET /api/inspection/active`：查询当前活跃巡检会话

2. 分类匹配：在对应分类下检索规范条款，按关键词相关度排序

4. 匹配结果存入 `Hazard.matched_regulations_json`，整改通知单自动填入规范依据

## 19. 微信小程序端

### 19.1 产品定位与功能范围

微信小程序端是系统第四个业务终端，面向专监、监理员、总监/总代以及被授权的施工协作人员。首期必须支持：

- 账号登录与微信身份绑定，复用现有 JWT、RBAC 和项目隔离规则
- 智能监理助手文字问答、按住说话、语音转文字、回答文字展示与语音播放
- 调用手机摄像头拍照、连续录像，调用系统相册选择图片/视频
- 图片上传后自动加水印、计算哈希，可直接发起隐患识别并关联工作记录
- 录制视频上传并关联巡视、验收、见证、旁站、隐患或整改记录
- 发起、接听和结束一对一音视频通话；后续可扩展多人会议
- 查看待办、派单、隐患及整改信息，接收微信服务通知
- 将派单、隐患或整改任务生成小程序分享卡片/链接；接收方进入后仍需登录并通过项目权限校验

小程序端不提供系统设置、规范库维护、批量台账导出等 PC 专属功能。

### 19.2 媒体能力

| 能力 | 需求 |
|---|---|
| 拍照 | 支持前后摄像头切换、重拍、预览、确认上传；拍摄后由后端生成可信服务端时间水印 |
| 录像 | 支持开始/暂停/结束、预览、取消和上传；记录时长、大小、分辨率及关联业务类型 |
| 录音 | 支持按住说话或点击开始/结束，上传至 STT 接口后将文本交给监理智能体 |
| 音频通话 | 支持呼叫、振铃、接听、拒绝、静音、扬声器切换、挂断、弱网提示 |
| 视频通话 | 支持摄像头开关、前后切换、麦克风开关、大小窗远端画面、挂断和网络质量提示 |

摄像头和麦克风仅在用户主动触发功能时申请授权；拒绝授权时给出可理解的降级提示和设置入口，不得后台静默采集。

### 19.3 音视频通话业务流程

```
发起人选择项目成员
  ↓
后端校验双方项目归属、角色权限和会话资格
  ↓
创建 call_session，服务端签发短期 RTC 凭证
  ↓
通过 WebSocket 在线信令 + 微信服务通知发送来电
  ↓
接收人接听/拒绝；接听后双方进入 RTC 房间
  ↓
通话中可切换音频/视频、静音、摄像头及扬声器
  ↓
任一方挂断或超时，后端结束会话并记录审计日志
```

通话音视频流由合规 RTC 服务传输，业务后端只负责房间、短期凭证、成员权限、信令和审计。默认不录制通话；如后续增加云端录制，必须二次明确告知并取得各方同意。

### 19.4 认证、隐私与安全

- 小程序通过 `wx.login` 获取临时登录凭证，后端使用 AppSecret 换取微信用户标识；AppSecret 只保存在服务端
- 首次登录需将微信身份绑定到现有监理通账号，绑定成功后签发系统 JWT
- API、上传和 WebSocket 必须使用已备案 HTTPS/WSS 合法域名，不在小程序中存放 AI Token、RTC Secret 或 AppSecret
- 图片、视频和录音上传前校验格式、大小与时长；服务端重新生成文件名并执行访问控制
- 记录摄像头、麦克风、相册、位置等权限用途，配置隐私保护指引和用户撤回路径
- RTC 凭证短期有效并绑定用户、房间和过期时间；服务端校验项目成员关系，禁止任意加入房间
- 通话日志仅记录会话 ID、项目、成员、媒体类型、开始/结束时间和结束原因，不默认保存音视频内容

### 19.5 弱网、失败与同步规则

- 拍照、录像和录音上传失败时进入本地待同步队列，用户可取消或重试
- 重试请求携带客户端幂等键，避免重复创建影像、隐患和工作记录
- 通话断网时显示重连状态，短时间内使用原会话重连；超时后结束并保留异常原因
- 上传成功的数据立即进入统一业务库，并同步至眼镜端、手机浏览器端和 PC 端

### 19.6 验收标准

1. 授权摄像头后可完成拍照和录像，文件可预览、上传并在 PC 端查询。
2. 授权麦克风后可录音，STT 返回文本并成功调用监理智能体。
3. 图片可完成加水印、哈希取证和隐患识别，来源标记为 `miniprogram`。
4. 两名同项目授权用户可完成音频/视频呼叫、接听、拒绝、切换设备和挂断。
5. 非项目成员、过期 RTC 凭证、无效 JWT 均无法加入通话或读取媒体。
6. 用户拒绝摄像头/麦克风权限时不崩溃，并可继续使用不依赖媒体的功能。
7. 弱网下上传可重试且不产生重复记录，通话中断有明确状态和审计记录。

> **文档说明**：本需求文档基于项目现有功能实际梳理 + 最新需求文本（《需求文本_extracted.txt》）整合，涵盖系统全部业务逻辑。四端业务定位（眼镜端=现场零手持作业端、手机浏览器端=便携经办端、微信小程序端=微信生态移动协作端、PC 端=后台管控归档端）、核心业务能力与流程均已纳入。如后续有新增功能或业务调整，请同步更新本文档。
