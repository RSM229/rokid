## 3. 后端：登录拦截（最容易漏，两端都要）

### 3.1 `auth.py::login`（第 506 行）
在 `is_active` 检查后插入：
```python
if user.audit_status == AUDIT_PENDING:
    raise HTTPException(403, "账号待管理员审批，请稍后再试")
if user.audit_status == AUDIT_REJECTED:
    raise HTTPException(403, f"注册申请已被拒绝{原因}，请联系管理员")
```
> 与 `is_active` 分工：`audit_status` 管**进门**，`is_active` 管**停用**。

### 3.2 `miniprogram_auth.py::_token_response`（唯一发 token 出口）
在 `org_role in ORG_ROLES` 检查旁加同款 `audit_status` 拦截 → 一次覆盖登录/绑定/注册/扫码全部路径。
另：`/login` 已绑定分支遇到 `pending`，返回 `{bound:false, …}` 语义（避免出现"能进页面但用不了"的死局）。

## 4. 后端：审批接口（新，`auth.py`）

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/auth/registrations?status=pending` | `user_approve` | 分页；只列**本企业**（`org_id` 相同） |
| `POST /api/auth/registrations/{user_id}/approve` | `user_approve`（+ 目标项目 `member_manage`） | 入参 `{project_id?, roles:[...], org_role?}`；`org_role` 仅超管 |
| `POST /api/auth/registrations/{user_id}/reject` | `user_approve` | 入参 `{reason}` |

**批准 = 一个事务五件事**：
1. `audit_status='approved'` + `approved_by` + `approved_at`
2. `users.org_id` 补齐
3. `users.role` = 岗位集合主岗（兜底展示）
4. `project_id` 有值 → `INSERT/UPSERT project_members(project_id, user_id, role=主岗, extra_roles=附加岗)` ← **归属落定**
5. 写 `security_audit`（`user_approve` / `user_reject`）

**约束**：排他岗位（项目已有总监则不能再批「总监理工程师」）；**不得批自己**（403）；只批本 `org_id`。

## 7. 验收用例（§8.8.8，共 8 条）

1. 超管发码 → 用码注册 → **登录被拦（待审批）** → 管理员批（选项目 1 + 专业监理工程师）→ 登录成功、权限 = 专监
2. 小程序凭码注册 → 同样 pending → 批并选项目 → 可用
3. 拒绝（附理由）→ 登录 403「已拒绝」→ 改判 approved → 可登录
4. 批「总监理工程师」到已有总监的项目 → **必须拒绝**（排他岗位）
5. 审批人 == 自己 → 403
6. **存量 5 账号（`audit_status` 默认 approved）→ 登录不受影响**（回归底线）
7. 一码 3 人用（max_uses=5）→ 各自 pending → 批到**不同项目/岗位** → 归属权限互不相同
8. 码上 role=监理员 → 审批指定专监 → `project_members.role` **必须是专监**（`users.role` 主岗仍监理员兜底）
