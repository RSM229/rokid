## 0. 摘要

监理通小程序是「眼镜 + 小程序 + Web 后台 + 移动 H5」四端体系中的现场入口。技术上采用**微信原生小程序 + TypeScript strict**，共 **29 个页面**、**5 个自定义 Tab**、**12 个服务模块**、**5 个自定义组件**，无分包、无第三方 UI 框架、无全局状态管理库。

核心是 `pages/agent`——一个 5598 行的对话式智能体工作台。它把「语音 / 拍照 / 文件」输入转成「请求计划 → 复核计划 → 业务落库 → 文书生成」的可确认流程，并通过持久执行 ID、进度轮询、草稿和上传队列处理现场弱网。

后端为单 FastAPI 服务，注册 **40 个路由文件**，统一挂载在 `/api` 下，生产由 Nginx 终止 TLS，数据落 MariaDB（库 `gdjl`），文件区 `/uploads`、`/exports` 已改为受控鉴权端点。

## 4. 启动与生命周期

`app.ts` 只有 49 行，职责克制：

| 时机 | 行为 |
|---|---|
| `onLaunch` | 注册网络状态监听；首次启动展示新手指引；网络恢复时补传队列 |
| `onShow` | 已登录且队列非空时静默补传 |
| 登录页 `onLoad` | 已有 token 直接跳工作台 |

### 4.1 新手引导

```text
启动
 ├─ 已看过 gdjl_onboarded_v1 → 正常进入
 └─ 未看过
     ├─ 冷启动 query 带 id / item_id（通知、分享）→ 不打断，直接去目标页
     └─ 否则 reLaunch → pages/guide/index
```

引导页看完或跳过后写 `gdjl_onboarded_v1`，后续不再弹。

### 4.2 网络恢复补传

```text
wx.onNetworkStatusChange(isConnected)
  └─ isConnected && token && 队列非空
       └─ uploadQueue.retryAll(skipAudio = true)
            └─ 成功数 > 0 → Toast 提示
```

`queueRetrying` 防止并发重入；语音不参与全局补传，因为转写文本必须由对话页承接。

## 5. 鉴权与会话

### 5.1 存储键

所有 key 都带环境作用域：

```ts
storageScope = encodeURIComponent(apiBaseUrl)

gdjl_<scope>_access_token
gdjl_<scope>_user_info
gdjl_<scope>_bind_token
gdjl_<scope>_force_pwd_skipped_user
gdjl_<scope>_media_upload_queue
```

这样本地后端与生产后端的登录态、上传队列天然隔离。

### 5.2 登录链路

```text
wx.login() → code
   │
   ├─ POST /api/miniprogram/auth/login   (auth: false)
   │      │
   │      ├─ bound = true
   │      │     └─ 保存 access_token + user → 工作台
   │      │
   │      └─ bound = false
   │            └─ 返回 bind_token
   │                 ├─ 绑定已有账号：POST /miniprogram/auth/bind
   │                 │     username + password + role + wx_nickname
   │                 ├─ 微信自助注册：POST /miniprogram/auth/wechat-register
   │                 │     生成零权限裸用户，随后用邀请码加入项目
   │                 └─ 公司级账号改绑：服务端返回 rebind_from_org_account
   │
   └─ 登录后路由
         must_change_password 且未跳过 → /pages/force-password/index
         存在 gdjl_pending_route        → 回原页面
         否则                           → /pages/agent/index
```

### 5.3 账号能力

| 能力 | 页面 | 接口 |
|---|---|---|
| 微信登录 | `login` | `POST /miniprogram/auth/login` |
| 绑定已有账号 | `login` | `POST /miniprogram/auth/bind` |
| 微信自助注册 | `register` | `POST /miniprogram/auth/wechat-register` |
| 绑定状态 | `account-security/binding` | `GET /miniprogram/auth/status` |
| 更新微信昵称/头像 | `account-security/binding` | `POST /miniprogram/auth/wechat-profile` |
| 解绑微信 | `account-security/binding` | `POST /miniprogram/auth/unbind` |
| 设置/修改密码 | `account-security/credentials`、`force-password` | `POST /miniprogram/auth/password` |
| 密保问题 | `security` | `GET/PUT /auth/me/security-questions` |
| 忘记密码 | `forgot` | `POST /auth/forgot/questions · verify · reset` |
| 加入项目 | `join-project` | `POST /auth/invite-codes/{code}/join` |
| 当前用户 | `account-security/identity`、`mine` | `GET /auth/me` |
| 眼镜绑定二维码 | `settings` | `POST /auth/glasses/qr-create` |

### 5.4 401 兜底

`services/request.ts`：

1. 每个请求自动带 `Authorization: Bearer <token>`。
2. 返回 **401** 时：
   - 把当前页面 `route + options` 写入 `gdjl_pending_route`；
   - `session.clear()`；
   - `wx.reLaunch('/pages/login/index')`。
3. 登录成功后由 `login/enterAfterLogin()` 回跳原页面。

`utils/guard.ts` 的 `requireLogin()` 复用同一个 pending route，用于分享链接、服务通知直达。

> 注意：`gdjl_pending_route` 没有带 `storageScope`，切换后端环境时可能与旧环境残留冲突。

## 6. 网络与文件访问层

### 6.1 环境配置

```ts
productionApiBaseUrl = ext.apiBaseUrl || 'https://www.baize.gdces.cn/api'
localApiBaseUrl      = ext.localApiBaseUrl || 'http://127.0.0.1:8001/api'

PREFER_LOCAL_BACKEND = false
useLocalBackend = develop && PREFER_LOCAL_BACKEND && ext.useLocalBackend !== false
```

| 规则 | 说明 |
|---|---|
| 生产 / 体验 | 始终走生产域名 |
| 本地联调 | 必须显式打开 `PREFER_LOCAL_BACKEND`，且仅 develop |
| mock 登录 | 仅本地后端 + develop + `mockWechatLogin === true` |
| `ext.json` | 由第三方平台/部署流程注入，避免改源码重新合并 |
| 域名白名单 | request/uploadFile/downloadFile：`https://www.baize.gdces.cn`；socket：`wss://www.baize.gdces.cn` |

### 6.2 `request.ts`

- 统一入口 `request<T>(path, options)`。
- 默认 JSON、30s 超时、自动鉴权。
- 错误统一为 `ApiRequestError`：
  - `statusCode`
  - `code`
  - `networkError`
  - `timedOut`
- 兼容 FastAPI 的 `detail` 字符串或对象。
- 本地后端连接失败时给出明确提示，而不是裸 `request:fail`。

### 6.3 媒体 URL 与 token

后端 `/uploads`、`/exports` 已从无鉴权 StaticFiles 改为 `files.py` 受控端点（需登录 + 项目归属校验）。

小程序的 `<image>`、`wx.previewImage` 无法携带 `Authorization` 头，因此：

```ts
absoluteMediaUrl(path)   // 受控路径追加 ?access_token=...
refreshMediaToken(url)   // 替换历史缓存中的旧 token
```

| 优点 | 缺点 |
|---|---|
| 图片/导出文件可直接展示与预览 | token 会进入 URL、日志、截图、转发 |
| 不需要额外下载代理 | token 失效后历史 URL 需刷新 |

### 6.4 上传接口

| 方法 | 后端接口 |
|---|---|
| 图片 | `POST /media/images` |
| 视频 | `POST /media/videos` |
| 视频分段 | `POST /media/videos/segments/{recordingId}/{index}` |
| 视频合并 | `POST /media/videos/segments/{recordingId}/merge` |
| 视频下载 | `GET /media/videos/segments/{recordingId}/download` |
| 音频转写 | `POST /media/audio/transcribe` |
| 文档解析 | `POST /media/document/parse` |
| 带照片建记录 | `POST /work-record/create-with-photos` |
| 其他记录 | `POST /work-record/other` |

所有上传统一带 `idempotency_key`；错误映射为 401/413/429/502-504 的用户可读文案。

### 6.5 WebSocket 现状

后端提供 `/api/ws`，但当前小程序源码中**未发现 `wx.connectSocket` 调用**。Agent 长任务使用：

- `GET /agent/requests/{request_id}` 轮询进度事件；
- `GET /agent/executions/{execution_id}` 恢复持久执行。

## 7. 上传与弱网队列

`services/uploadQueue.ts`：

| 机制 | 实现 |
|---|---|
| 存储 | `gdjl_<scope>_media_upload_queue` |
| 上限 | 20 条，`items.slice(-20)` |
| 临时文件 | 入队前 `persistTempFile()` 转存为持久文件 |
| 幂等 | 每条独立 `idempotencyKey` |
| 批量重试 | `retryAll(skipAudio)`，网络恢复 / `onShow` 触发 |
| 单条重试 | `retryOne(id)`，主要给语音用 |
| 中止条件 | token 失效立即 break，避免连环 401 |
| 写回策略 | 重读最新队列，按 id 合并，避免覆盖期间新增/取消 |
| 丢弃策略 | 不可重试错误（文件失效、内容不合规）直接出队 |

> 风险：超过 20 条时 `slice(-20)` 会静默丢弃最旧条目，用户无感知。建议入队前提示或拒绝。

## 12. 典型链路

### 12.1 现场拍照 → 隐患 → 文书

```text
capture 拍照 / 录像
  → /media/images 或 /media/videos（带 idempotency_key）
  → 弱网失败 → uploadQueue 入队 → 网络恢复补传
  → /hazard/commit-candidates（VLM 识别候选）
  → 工作台勾选确认
  → /hazard/* 落库
  → 复核计划确认
  → /form-docs/generate 或 /document/create-from-schema
  → documents/detail → 签名 / 签章 / 导出 PDF
```

### 12.2 语音对话 → 工作记录

```text
按住麦克风录音
  → /media/audio/transcribe
  → 文本进入对话页或语音工作会话
  → /agent/request-plan
  → /agent/chat
  → 字段候选 / 内联表单
  → /work-record/* 建记录
  → 可选：/document/generate-with-llm 生成日报
```

### 12.3 协作待办

```text
todo/compose 发起
  → POST /collaboration（成员、截止时间、关联业务）
  → 对方 todo 收件箱 GET /collaboration/inbox
  → 接受 / 拒绝 / 开始 / 完成
  → 完成后校验关联业务是否真正完成
  → 可催办 / 转派 / 撤回
```

### 12.4 长任务恢复

```text
POST /agent/chat
  → 客户端超时
  → 使用 execution_id 调 GET /agent/executions/{id}
  → 间隔 0 / 800 / 1600 / 3000 ms 重试
  → status = COMMITTED / FAILED 即停止
  → 404 视为执行不存在，回到普通错误处理
```

## 14. 架构评价与建议

### 14.1 做得好的地方

- 服务层边界清晰：`request / session / auth / upload / uploadQueue` 职责单一。
- TypeScript strict + 统一错误类型，弱网、超时、401 都有显式分支。
- 幂等键 + 持久上传队列 + 断网补传，贴合现场弱网场景。
- Agent 采用「计划 → 复核 → 执行 → 持久恢复」，避免模型直接写库。
- 媒体文件鉴权、权限版本头、生产关闭 OpenAPI，安全意识较好。
- 测试覆盖 agent 流程、上传队列竞态、协作待办、复核计划等关键路径。

### 14.2 风险与建议

| 优先级 | 风险 | 说明 | 建议 |
|---|---|---|---|
| P1 | 工作台 God Page | `agent/index.ts` 5598 行、WXML 802 行 | 按聊天 / 复核 / 进度 / 表单 / 附件 / 语音拆模块或组件 |
| P1 | 主包偏大、无分包 | `agent` 479 KB、`kb` 132 KB、`work` 97 KB | 至少把 `kb`、`documents`、`account-security` 拆成分包 |
| P1 | URL 带 token | `/uploads`、`/exports` 使用 `?access_token=` | 改短时效签名 URL 或一次性 ticket |
| P2 | 队列静默丢最旧 | `slice(-20)` 超限直接丢 | 入队前提示或拒绝并告知用户 |
| P2 | 无 WebSocket | 后端有 `/ws`，前端纯轮询 | 长任务可接 WS，降低轮询压力 |
| P2 | pending route 未分环境 | `gdjl_pending_route` 无 `storageScope` | 改为带作用域的 key |
| P2 | 类型定义偏薄 | `types/index.ts` 仅 16 行 | 抽出 `types/api.ts`，与后端 schema 对齐 |
| P3 | 文档漂移 | 旧架构文档、README、API_INVENTORY 过期 | 以本文为准更新 `docs/` |
| P3 | 遗留空目录 | `wechat-miniprogram/pages/` 为空 | 删除，避免误判结构 |

### 14.3 建议的演进顺序

1. **先拆工作台**：把 `pages/agent` 的复核计划、进度追踪、附件处理拆成独立模块，降低改动风险。
2. **再拆分包**：优先 `kb`、`documents`、`account-security`。
3. **替换媒体 token 方式**：使用短时效签名 URL，避免长期 token 出现在 URL。
4. **补全共享 API 类型**：从后端 OpenAPI 生成或手写 `types/api.ts`。
5. **更新文档与清理遗留目录**。
