第一部分　认识监理通

1.1 监理通是什么

监理通（内部代号「白泽」）是一套面向建设工程监理行业的 AI 工程监理智能体。它把监理人员日常最繁重的四件事——现场记录、隐患发现、文书编制、台账归集——搬到了手机和 AI 上。

一句话概括：在现场用手机（或 AR 眼镜）说一句、拍一张，系统自动帮你生成规范的监理记录与文书。

1.2 系统由哪几部分组成

监理通不是一个"单一软件"，而是三端协同 + 一个后端：

组成载体定位谁用
微信小程序手机微信现场作业主力：拍照、录音、填报、查看全体监理人员
Web 管理后台电脑浏览器管理与看板主力：立项、建号、审批、派单、台账、配置总监及以上
Rokid AR 眼镜端智能眼镜第一视角免手作业（语音指令 + 第一视角拍摄）现场监理人员
云端后端服务器三端共用同一套数据与权限——

💡 为什么要三端？ 现场监理的两只手往往被图纸、卷尺、安全帽占用，掏手机都费劲——眼镜解决"免手"，手机解决"精细填报"，电脑解决"批量管理与看板"。三者数据实时同步：小程序上刚拍下的隐患，Web 后台刷新即见。

1.3 访问方式

  • 微信小程序：微信内搜索小程序名，或扫描项目组提供的二维码
  • Web 管理后台：浏览器打开 https://www.baize.gdces.cn/admin/

🔴 地址不带端口（标准 443），且必须带 /admin/ 前缀。建议第一次打开后加入浏览器收藏夹。

🔴 登录后请勿在浏览器直接按 F5 刷新子页面（历史遗留问题，已在修复中）；如遇白屏或 404，回到上述完整地址重新进入即可。

第二部分　账号与登录（从零开始）

2.1 先搞懂：监理通的账号是"两层"的

这是初学者最容易混淆的地方，先看清楚：

                 ┌──────────────────────────────┐
   公司级（跨项目） │  超级管理员  |  管理员         │   ← 管人、管项目、管配置
                 └──────────────────────────────┘
                 ┌──────────────────────────────┐
   项目级（本工程） │  总监 / 总代 / 专监 / 监理员   │   ← 干活、记录、报审
                 │  资料员 / 见证员 / 安全监理员   │
                 └──────────────────────────────┘
  • 公司级角色：由超管在「用户管理」里授予，跨所有项目生效
  • 项目级岗位：由项目成员管理分配，只在被分配的那个项目里生效
  • 一个人可以同时拥有两层、以及多个项目级岗位——权限取并集

💡 为什么这么设计？ 因为监理行业的真实情况是"一人多岗、一岗多项目"。传统系统把"身份"写死，导致一个人兼岗就得开两个账号，数据也分裂。监理通用"岗位集合"模型，一个账号走遍所有项目。

2.2 九个岗位一览

岗位（中文）系统 key级别典型职责岗位性质
总监理工程师chief_supervisor项目级项目负责人：派单、审批文书、成员管理、看板🔒 每项目限 1 名
总监代表deputy_chief项目级代行总监职责（除成员管理与系统设置）🔒 每项目限 1 名
专业监理工程师special_supervisor项目级巡视、验收、旁站、见证、签章可叠加
监理员inspector项目级巡视、隐患识别、工作记录可叠加
资料员documenter项目级资料登记、台账管理可叠加
见证员witness项目级见证取样可叠加
安全监理员safety_supervisor项目级安全巡视、隐患识别可叠加
超级管理员super_admin公司级一切：立项、建号、发邀请码、解绑微信、配置权限跨项目
管理员admin公司级人员审批、成员管理（跨项目）跨项目

🔴 "可叠加"的含义：一个人可以同时是"专业监理工程师 + 见证员"，权限自动合并。但总监与总监代表是排他的——一个项目只能有一名总监（监理规范要求），也不会出现在"兼岗"选项中。

2.3 获得账号的三条路径

路径适用场景操作方
A. 邀请码自助注册（推荐）新员工入职你注册，管理员发码
B. 管理员直接建号批量/特殊账号全部由管理员完成
C. 已有账号 + 微信绑定账号最早在 Web 建的你绑定

无论哪条路，最终都需要管理员把你"分配进项目"，你才能在项目里干活。

2.4 路径 A：用邀请码注册（小程序）

  1. 打开监理通小程序，在登录页点「还没有账号？立即注册」
  2. 依次填写：
字段说明
用户名登录用，建议用姓名拼音，如 zhangsan
真实姓名用于文书署名、通讯录显示，务必填真名
手机号联系方式
密码至少 8 位
确认密码再输一次
公司邀请码🔴 必填，向管理员索取
  1. 页面会显示「岗位：xxx　由邀请码决定」——你无法自选岗位，这是防止越权注册的设计
  2. 点「注册」提交

⚠️ 提交后不等于能登录：页面提示「提交后需管理员审核，并分配到项目，审核通过后即可登录」。请等待管理员审批。

2.5 路径 A 变体：在 Web 后台注册

Web 登录页点「立即注册」，字段与小程序一致，另需填写「公司/团队名称」。同样必须持邀请码，同样需要管理员审核。

🔴 Web 与小程序注册的岗位规则完全一致：都强制校验邀请码，岗位一律取自邀请码上绑定的角色。

2.6 等待审批：这段时间发生了什么

  1. 你的账号状态为 待审批（pending）
  2. 有「人员审批」权限的管理员会在「用户管理」中看到你，并选择：
  • 批准 → 账号可用；同时完成分配项目等动作
  • 驳回 → 需填写理由，你可在注册/登录时看到驳回原因
  1. 审批通过后，用你的用户名 + 密码登录

💡 为什么注册也要审核？监理文件是有法律效力的工程资料，人员准入必须留痕、可控。系统对每一次批准/驳回都记录了操作人与时间。

2.7 首次登录 · 小程序

  1. 打开小程序 → 微信授权 → 点「微信登录」
  2. 首次使用会提示「首次使用需要绑定已有监理通账号」，填写：
  • 用户名
  • 密码
  • 登记角色

然后点「确认绑定并登录」

  1. 绑定成功后，之后每次打开小程序直接「微信登录」即可，无需再输密码

💡 微信登录与密码登录是同一个账号，只是身份验证方式不同。绑定后手机端免密，电脑端仍用账号密码。

2.8 首次登录 · Web 后台

  1. 打开 https://www.baize.gdces.cn/admin/
  2. 输入 用户名 + 密码
  3. 🔴 「选择角色」保持空（自动识别，推荐） ——系统会根据你的账号岗位自动加载对应权限
  • 只有在你明确知道自己在做什么、且账号确实有多重身份需要指定时才手动选择
  • 选错角色会提示「无效角色」或进入错误的功能集

2.9 让同一账号在两端都能用（设置登录密码）

如果你的账号最早是通过微信创建的，那么它默认没有密码，无法登 Web 后台。解决办法：

  1. 小程序 → 底部「我」→「我的工作」区域上方找到设置登录密码入口
  2. 设置一个 ≥8 位 的密码
  3. 之后即可用「用户名 + 密码」登录 Web 后台，数据完全同步

2.10 微信绑定管理

  • 查看绑定：「我」页面可看到当前微信的绑定时间与最近登录时间
  • 解绑：点击解绑后，退出登录并重新登录即可绑定当前微信（页面顶部有说明）
  • 被占用的提示：
  • 提示「该微信身份已绑定其他账号」→ 如果旧账号是公司级账号或已停用，系统会自动释放；否则请联系超管在「微信绑定管理」中解绑旧账号
  • 注册页提示微信被占 → 同上

⚠️ 不要用超管/公司级账号绑定微信（会导致该微信在注册/绑定时占用冲突）。公司级账号请在 Web 后台使用。

2.11 忘记密码怎么办

你的情况处理方式
微信已绑定小程序「我」→ 设置登录密码，免旧密码重设
未绑微信联系超管，在「用户管理」中重置密码
记得密码想改「我」→ 设置登录密码

2.12 账号常见问题速查

现象原因解决
登录提示「无效角色」角色下拉与账号岗位不符清空「选择角色」，用自动识别
提示「账号待审批」注册后管理员未批联系管理员审批
登录后菜单很少未被分配进项目请管理员在「项目成员管理」加入你
小程序 403 / 打不开账号被停用或公司级账号误绑微信联系超管
换了微信号旧微信仍绑定超管在「微信绑定管理」解绑后重新绑定

第三部分　微信小程序使用指南（现场作业）

3.0 界面总览：底部五个入口

小程序底部固定五个标签，工作台在正中间：

┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 隐患识别  │ 工作记录  │  工作台   │  资料库   │    我    │

      拍照识别       填报与查阅     对话式入口     知识检索    个人设置

💡 为什么把「工作台」放中间？因为它是最常用的入口——用一句话就能调起任何功能，相当于整个 App 的"总控台"。

3.1 工作台（中间标签）——一句话干活

工作台是一个 AI 对话界面（智能体名叫「白泽」）。你可以按住说话，也可以打字。

3.1.1 三个快捷卡片

对话页顶部通常有三个常用卡片，点一下即执行：

卡片效果
拍照识别安全隐患打开相机 → 选中照片 → AI 识别隐患
查询规范资料库进入规范检索问答
生成今日监理日志自动汇总当天工作，生成监理日志

3.1.2 可识别的语音/文字指令

直接说这些话，系统会跳到对应功能：

🔴 两条安全铁律（系统强制）：

  1. 超管不能给自己降级
  2. 系统必须保留至少一名启用中的超管

💡 为什么？公司级角色是"最高权限"，如果允许自我降级或允许把最后一个超管取消，整个公司就再也没人能授权了——系统会永久锁死。

4.11.2 修改权限的 5 条约束

  1. 不能授予你自己都没有的权限
  2. 项目级岗位不能持有公司级权限
  3. 目录之外的权限键会被拒绝（不能凭空造权限）
  4. super_admin 不可修改（它恒定拥有全部权限）
  5. 所有修改写入审计日志

4.11.3 即时生效

改完保存后，正在使用系统的用户会在下一次请求时自动刷新权限（无需重新登录）。

⚠️ 改权限前请想清楚：例如把「文书审批」从总监身上取消，总监就再也批不了文书了。

🔴 角色 key（如 chief_supervisor）不可在界面上增删——角色是系统级定义，不是配置项。

第五部分　管理员典型工作流

5.1 新项目上线（7 步）

1. 立项      → 项目管理 → 新建项目（名称/编号/简称/地点）  【超管】
2. 定岗位    → 想清楚这个项目需要哪些岗位、各几人
3. 发码/建号 → 邀请码管理 发码（选对岗位）  或  用户管理 新增用户  【超管】
4. 人员注册  → 员工用邀请码注册，等待审批
5. 审批      → 用户管理 → 批准（记审批人与时间）      【管理员/超管】
6. 分配项目  → 项目管理 → 项目成员管理 → 加入项目并定岗  【总监/超管】
7. 交底      → 把本说明书第 3 部分发给现场人员

5.2 新员工入职

  1. 超管在「邀请码管理」新建邀请码：选对该员工岗位，设使用次数与有效期
  2. 把邀请码给员工
  3. 员工在小程序或 Web 注册（详见 2.4 / 2.5）
  4. 管理员「批准」
  5. 总监在「项目成员管理」把他加入项目并设定主岗（如需兼岗，再加兼职岗位）

5.3 员工离职

  1. 项目成员管理 → 移出项目（记录离场时间）
  2. 用户管理 → 停用账号
  3. 微信绑定管理 → 解绑微信（释放给下一个使用者）

顺序很重要：先移出项目、再停用账号、最后解绑微信。

5.4 人员换岗 / 兼岗

  • 换岗：项目成员管理中修改其主岗
  • 兼岗：在兼职岗位上追加（可叠加的 5 类岗位）。权限自动取并集
  • 🔴 总监与总监代表每项目各限 1 名，且不能作为兼职岗位添加

5.5 项目结项

  • 「项目管理」→ 对目标项目执行结项：状态→已完工，在岗成员批量离场
  • 如需恢复，执行恢复操作

5.6 权限调整（什么时候该动「角色权限」页）

场景建议
想让监理员也能看台账「数据档案 → 台账」勾给 inspector
想让专监也能批文书慎重——审批权通常只给总监
新角色需求⚠️ 角色不可新增，应通过"权限配置"组合实现

6.3 权限是怎么算出来的（三条规则）

  1. 并集：公司级角色权限 ∪ 各项目岗位权限，全部合并
  2. 跨两层：member_manage 是唯一同时出现在两层的键
  3. 🔴 super_admin 恒为全量：无论矩阵怎么配，超管永远拥有全部 27 项权限，且该角色不可被修改（这是系统的"逃生通道"）

第七部分　常见问题（FAQ）

账号与登录

Q1　登录提示「无效角色」？角色下拉与账号实际岗位不符。把「选择角色」清空（用自动识别）再登录。

Q2　微信登录提示「该微信身份已绑定其他账号」？该微信绑过别的账号。若旧账号是公司级或已停用，系统会自动释放；否则联系超管在「微信绑定管理」解绑。

Q3　微信注册的用户怎么登 Web 后台？小程序「我」→ 设置登录密码（≥8 位）→ Web 用「用户名 + 密码」登录，角色留空。两端数据同步。

Q4　邀请码从哪里获取？联系超级管理员，在后台「邀请码管理」生成。码决定你的岗位，务必和管理员确认岗位正确。

Q5　注册提交后为什么还不能登录？注册后账号处于待审批状态，需管理员批准。请等待或联系管理员。

Q6　忘记密码？微信已绑定：小程序「设置登录密码」可免旧密码重设；未绑微信：联系超管重置。

Q7　注册时提示微信被占用？同 Q2。小程序会自动释放"小程序端不可用"的旧绑定。

小程序

Q8　底部怎么只有五个标签？这是设计：隐患识别 / 工作记录 / 工作台 / 资料库 / 我。其余功能都从「工作台」用一句话或快捷卡片调起。

Q9　工作台说话没反应？检查是否授予了麦克风权限；或改用打字输入。日常可用指令见 3.1.2。

Q10　拍照识别不出隐患？AI 会明确返回「未识别到明显安全隐患」，这不代表系统故障。可换更清晰的角度、更近的距离重拍。

Q11　在电脑上拍的隐患，手机上多久能看到？三端数据实时同步，刷新即可见。

Q12　「资料库」和「规范资料库」是一回事吗？不是。「规范资料库」是规范法规检索；「资料库」是你的个人/共享资料库（可建库、可凭邀请码加入）。

Q13　通知收不到？在「我」→ 服务通知订阅，订阅「审批通知」「派单与隐患通知」。

Web 后台

Q14　网页刷新后 404 / 白屏？历史遗留问题（在子页面按 F5 会 404）。回到 https://www.baize.gdces.cn/admin/ 重新进入即可。

Q15　左侧菜单和说明书里写的不一样？菜单随权限自动增减。没有权限的项不显示，这是正常的。

Q16　台账 / 文书审批 / 派单在哪里？不在左侧菜单，从「工作台」输入指令进入（如输入"台账""文书审批"）。

Q17　为什么系统提示我"不能审批自己"？人员审批有互斥约束：管理员不能批自己的申请，且只能批本组织的人。请让其他管理员处理。

Q18　为什么不能取消最后一个超管的角色？系统强制保留至少一名启用中的超管——否则公司将永久失去授权能力。

管理员

Q19　邀请码列表是空的，码丢了吗？不是。列表只显示启用中的邀请码，已停用/用尽的码不显示。

Q20　邀请码能发公司级角色吗？不能。公司级角色只能由超管在「用户管理」中授予。

Q21　一个项目能有几个总监？1 个。总监与总监代表都是排他岗位，每项目各限一名。

Q22　改了权限要通知用户重启吗？不需要，即时生效。

Q23　项目结项后人员还在项目里吗？不在。结项会批量把在岗成员置为离场并记录时间。如需恢复，可执行恢复操作。
