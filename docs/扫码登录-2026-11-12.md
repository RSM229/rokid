# 扫码登录（小程序扫一扫 → Web 登录）— 2026-11-12

## 做什么

Web 登录页新增「扫码登录」：网页展示二维码，用户用「监理通」小程序
（我的 → 扫码登录网页端）扫码确认，网页自动登录成同一账号。

## 流程

```
web(未登录) --create--> 后台生成 {ticket, secret, code, qr_text}
    │ 显示二维码 + 校验码，2s 轮询 status
    ▼
小程序 wx.scanCode 扫到 GDJL-WEB-LOGIN:<ticket>:<code>
    → lookup（带小程序 JWT）拿校验码/浏览器/来源 IP
    → 弹窗确认（核对校验码，非本人可取消）
    → confirm：后台把 ticket 绑定到当前小程序账号
    ▼
web 轮询到 confirmed → 后台 _issue_token(user) → 直接进后台
```

## 接口（`/api/auth/scan-login/*`）

| 方法 | 路径 | 鉴权 | 作用 |
|---|---|---|---|
| POST | `/create` | 公开 | 生成 ticket/secret/校验码，返回二维码文本；120s 有效 |
| POST | `/lookup` | 小程序 JWT | 扫码后查询校验码、浏览器、来源 IP（脱敏） |
| POST | `/confirm` | 小程序 JWT | 确认登录，校验码不一致拒绝；绑定 user_id |
| GET | `/status?ticket&secret` | 公开（需 secret） | 轮询状态；确认后签发 Web TokenResponse（一次性） |

安全约束：

- 二维码里只有 ticket + 校验码，**secret 只回给 web**，扫到二维码也换不到 token
- ticket 120 秒过期、一次性；确认后只有对应 secret 能取一次 token
- confirm 必须带登录态；重复轮询返回 `used` 而不是误导性的「已过期」
- 错误 secret 403、错误校验码 400、超管在小程序登录阶段即被拦截（只能密码登录 Web）

## 实测（生产 443）

后端链路（chief 账号，脚本模拟小程序确认）：

```
create: code=RR7D expires_in=120
lookup: code=RR7D client=未知浏览器 ip=172.18.0.* user_name=csm
confirm: ok=True
status: confirmed user=chief role=admin has_token=True
poll_again: used
wrong_secret: HTTP 403
wrong_code: HTTP 400
```

Web 无头浏览器全链路：打开 `/login` → 扫码登录 → 二维码 + 校验码渲染 →
模拟小程序 confirm → **2 秒内自动跳到 `/dashboard`、token 落 localStorage、0 控制台报错**。

## 上线 / 配置

- 后端已 reload；Web 已部署（原地 rsync）
- **微信小程序后台需要把服务器域名改成不带端口**：
  `request/uploadFile/downloadFile → https://www.baize.gdces.cn`
  `socket → wss://www.baize.gdces.cn`
  否则真机模拟/预览会因域名不一致被微信拦截
- 小程序需重新「预览/上传体验版」才能看到「我的 → 扫码登录网页端」入口

## 已知限制

- 超管不支持扫码（小程序端 403）；继续用账号密码
- ticket 存内存，当前单 uvicorn 进程可用；多 worker/多实例需换 DB/Redis
- 微信开发者工具对 `wx.scanCode` 支持有限，必须真机验证
- 二维码登录天生有"骗扫"风险，已用校验码 + 「不是本人请取消」文案缓解

## 回滚

- 后端：`app/routers/auth.py.bak_before_scan`（服务器）
- Web：沿用原地 rsync，旧 dist 备份机制不变
