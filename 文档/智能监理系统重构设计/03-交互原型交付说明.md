# 工作资料整理交互原型

日期：2026-10-20

## 本次交付范围

在现有微信小程序新增独立的工作资料整理页，验证「输入资料 → 候选事项 → 业务日期及表式核对 → 计划记录预览」的交互。此次没有替换旧智能体执行链路。

入口：聊天空状态的「整理多张现场资料」。开发者工具也可以设置启动页面为 `pages/work-review/index`，不依赖后端登录即可查看该页。

## 可以体验的内容

- 五种示例场景：混合日期及缺失水印、九张图片九个日期、相同历史日期的多项工作、用途不明、纯文字。
- 资料数、事项数、计划记录数分别统计；示例分组可调整。
- 编辑事项名称、工程部位、工作情况；核对和明确确认业务日期。
- 一个事项选择多个表式，预览相应的多份计划记录。
- 单张图片拆成新事项、多个事项合并、移入待分配区、重新归属。
- 移除事项不会删除资料，资料退回待分配区。
- 合并不同日期后，业务日期清空并重新确认；资料自身的原始日期线索保持不变。
- 分组不完整时仍可预览草稿；确认分组会校验日期、表式、工作资料及待分配资料。
- 本地持久化草稿；每次业务编辑递增版本并使旧确认失效。

## 示例与实际处理的边界

页面使用项目图片库中的九张压缩缩略图（共约 0.6 MB）。所有日期线索、事项划分和候选内容都是明确标识的模拟数据，不是对图片执行 OCR 或视觉识别的结果。切换场景会替换本地草稿，页面先提示确认。

此页没有真实图片上传、OCR、模型调用、项目上下文获取、正式 schema 校验、专用字段填写、Word/PDF 渲染、数据库建档、签章或通知发送。表式选择仅用于验证交互，并不代表对应模板已接通。

「分组确认」只表示本地事项、日期、资料归属和表式选择得到确认，不代表正式记录完整、符合规范、已签发或已落库。预览会保留待补充的结论、专用字段及签章，不生成虚构结论。

本原型为简化调整过程，单张资料在编辑区暂时只能属于一个事项或待分配区；同一事项可以生成多份记录。生产架构中的证据与事项多对多关联仍按总体设计推进。

## 后续真实业务接入顺序

1. 依据实际模板确认可上线的表式版本、字段定义、必填条件和业务状态。
2. 后端保存请求与原始证据，异步提取内容、日期、部位及来源，返回带证据引用的观察结果。
3. 增加规划 API，综合用户要求和观察结果生成事项及表式候选；输入形式不承担业务路由。
4. 用真实候选替换原型 fixtures，保留人工调整、多轮补充和版本校验。
5. 按表式 schema 补齐字段，通过服务端校验后生成可追溯的业务草稿及模板预览。
6. 接入带版本和幂等键的正式确认命令，再实现签发及后续流程。
