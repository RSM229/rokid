## 一、系统概述

### 1.1 项目定位

"监理通"是一套面向建筑工程监理行业的智能体系统，依托 Rokid AI 眼镜、移动浏览器、微信小程序和 PC Web 四端协同，构建"眼镜现场采集 + 浏览器移动经办 + 微信内媒体协作 + PC SaaS 管理 + 云端 AI 识别"的一体化监理作业平台，覆盖巡视、验收、见证、旁站等监理现场全流程。

系统通过统一的云端后端对外提供 REST API 和实时信令，四端共享同一套业务数据与 AI 能力，确保数据一致性与角色协同。实时音视频媒体由合规 RTC 服务承载，业务后端负责授权、房间、信令和审计。

### 1.3 设计原则

- **四端协同**：眼镜端、手机浏览器端、微信小程序端、PC Web SaaS 端共用同一后端，按设备能力差异化分工。
- **零手持作业**：眼镜端与手机浏览器端均支持全程语音操控，适配现场双手占用场景。
- **云端智能**：AI 能力（VLM/LLM/STT）统一由后端代理，前端不持有任何模型 Token，保证安全与可维护性。眼镜端不部署本地模型，安全隐患识别通过云端 VLM API 完成。
- **分级降级**：LLM 采用"本地优先 + 三级降级"策略，VLM/STT 均有失败重试机制，保障核心链路可用性。
- **弱网可用**：现场端（眼镜端、手机端）支持弱网/离线本地缓存，联网后自动同步，不丢失影像与巡检数据。
- **角色隔离**：基于 RBAC 权限矩阵，总监理工程师、总监代表、专业监理工程师、监理员按权限访问对应功能；`admin` 为超级管理员账号。
- **防篡改可追溯**：影像记录使用 SHA256 哈希校验，水印不可篡改、不可编辑，导出文书自动添加含水印信息的防伪水印并支持电子签章。

**技术栈**：Vue 3.5 + Vant 4 + Pinia + Vue Router + axios + @vueuse/core + idb + vite-plugin-pwa。

**关键特性**：
- **TabBar 导航**：工作台 / 工作记录 / 影像 / 我的
- **离线队列**：写请求在离线时入队 IndexedDB（`request-queue` 对象仓库），联网后批量重放；只读请求离线时直接跳过
- **PWA 支持**：通过 `vite-plugin-pwa` 自动注册 Service Worker，`registerType: 'autoUpdate'`；manifest 配置独立品牌"监理便携经办端"
- **路由守卫**：未登录跳 `/login`；已登录访问 `/login` 跳工作台；登录后初始化 `app.init()`（在线/离线、同步队列）

**关键特性**：
- **InspectionBus**：单例对象（`object InspectionBus`），跨 Activity 共享当前巡检会话 ID 与状态

- **WatermarkOverlay**：在 Canvas 上绘制项目/时间/人员/位置水印，并计算 SHA256 用于防篡改
- **9 项菜单入口**：工作记录、监理文书、隐患识别、派单任务、规范查询、验收指引、AI 巡检、电子签章、个人设置
- **4 Tab 工作记录**：巡视/验收/见证/旁站，每类支持拍照与语音补充

### 3.6 规范库维护机制

**维护动作清单**：

| action | 入参 | 行为 |
|---|---|---|
| `add` | `name`、`category`、`content` | 新增规范条目 |
| `update` | `name`、`content` | 修改已有规范条目正文 |
| `delete` | `name` | 删除规范条目 |
| `move_category` | `name`、`target_category` | 调整规范所属分类 |
| `list` | - | 列出全部规范条目 |

**move_category 实现要点**：

1. 路由层校验 `target_category` 必填，否则返回 400
2. 调用 `regulation_category_service.move_category(filename, target_category)`
3. 服务层定位规范文件 → 修改其 metadata 中的 `category` 字段 → 重新分块入库（`RegulationChunk` 表同步更新）
4. 返回 `{ "action": "move_category", "name": ..., "from": <旧分类>, "to": <新分类> }`
5. 操作写入审计日志，记录操作人、时间、原分类、新分类

**前端入口**：`web-admin/src/views/KnowledgeBase.vue` 新增"规范库维护"Tab，提供分类下拉、批量移动、单条编辑操作。

### 3.7 电子签章技术方案

电子签章用于将监理人员手写签章图片嵌入到导出的 PDF 文书中，实现"签章人 + 时间 + 角色 + 哈希"四位一体的签署留痕。

**技术实现**：

| 组件 | 文件 | 职责 |
|---|---|---|
| 数据模型 | `models/signature.py` `Signature` | 存储签章图片路径、签章人、角色、激活状态 |
| 路由 | `routers/signature.py` | 5 个接口：upload / me / delete / sign / signed-pdf |
| 服务 | `services/signature_service.py` | 签章嵌入 PDF 核心 |
| 依赖库 | Pillow + pypdf + reportlab | 图片处理 + PDF 页面叠加 + 透明水印层生成 |

**签章嵌入流程**：

```
1. 签章上传：POST /api/signatures/upload
   ├─ 校验 PNG 格式（透明背景）
   ├─ 保存到 uploads/signatures/signature_{uid}_{ts}_{md5}.png
   └─ 写入 Signature 表，关联 user_id

2. 文书签署：POST /api/signatures/documents/{doc_id}/sign
   ├─ Body: { signature_id, password, position: "bottom-right|bottom-left|top-right|top-left" }
   ├─ 校验签章密码（bcrypt）
   ├─ 取文书导出 PDF 路径（来自 /exports/）
   ├─ embed_signature_to_pdf():
   │   ├─ 用 reportlab 在 A4 透明页上绘制签章图片 + 时间戳
   │   ├─ 用 pypdf 将透明页叠加到原 PDF 指定位置
   │   └─ 输出新 PDF（不覆盖原文件）
   ├─ 计算签章图片 SHA256 作为签署留痕
   └─ 更新 Document.signed_pdf_path / signed_at / signed_by

3. 下载已签 PDF：GET /api/signatures/documents/{doc_id}/signed-pdf
   └─ 返回 FileResponse
```

**安全控制**：
- 签章密码使用 bcrypt 哈希存储，签署时校验
- 签章图片 SHA256 写入审计，防篡改
- 签署位置固定四角，避免遮挡正文
- 原始 PDF 保留，签章写入新文件

### 3.8 云端 AI 巡检闭环架构

云端 AI 巡检闭环由 `InspectionSession` 模型 + `routers/inspection.py`（6 接口）+ `services/inspection_service.py` 协同实现，支持"启动会话 → 周期采集 → VLM 识别 → 命中隐患 → 自动联动整改 → 停止会话"全链路闭环。

**InspectionSession 状态机**：

```
            POST /api/inspection/start
                       │
                       ▼
              ┌─────────────────┐
              │  status=active  │  ← 周期采集（POST /{id}/capture）
              │  started_at     │     ├─ 叠加水印入库
              │  total_captures │     ├─ 调用 VLM 识别
              │  total_hazards  │     ├─ 命中→创建 Hazard + 自动匹配规范
              │                 │     └─ WebSocket 推送巡检人
              └────────┬────────┘
                       │
            POST /api/inspection/{id}/stop
                       │
                       ▼
              ┌─────────────────┐
              │  status=stopped │
              │  stopped_at     │
              └─────────────────┘
```

**API 清单**：

| 接口 | 路径 | 行为 |
|---|---|---|
| 启动巡检 | `POST /api/inspection/start` | 创建会话（同用户同时只允许一个 active 会话）；`frequency_seconds` 默认 5 |
| 停止巡检 | `POST /api/inspection/{session_id}/stop` | 置为 stopped；幂等 |
| 查询活动会话 | `GET /api/inspection/active` | 返回当前用户 active 会话 |
| 巡检统计 | `GET /api/inspection/{session_id}/stats` | 返回 captures/hazards 计数与时间分布 |
| 历史会话 | `GET /api/inspection/history` | 分页返回历史会话 |
| 采集识别 | `POST /api/inspection/{session_id}/capture` | 上传一张图片，触发水印 + VLM + 隐患创建 + 规范匹配 + WebSocket 推送 |

**自动联动**（在 `capture` 接口内）：

1. `apply_watermark_to_image` 叠加项目/时间/人员水印
2. 写入 `ImageRecord`，SHA256 入库
3. `ai_client.recognize_hazard` 调用 VLM 识别
4. 命中隐患时：
   - 创建 `Hazard` 记录，状态 `reported`
   - 调用 `regulation_matcher.match_regulations` 自动匹配规范条款，写入 `Hazard.matched_regulations_json`
   - 通过 `push_realtime` 向巡检人 WebSocket 推送 `inspection_hazard` 事件
   - 通过 `broadcast_to_project` 向项目内 PC 端推送 `hazard_detected` 事件
5. 更新 `InspectionSession.total_captures` / `total_hazards` / `last_capture_at` / `last_hazard_at`

### 3.9 WebSocket 实时推送架构

WebSocket 实时推送由 `routers/ws.py` 实现，提供多端实时同步能力，弥补原"通知队列内存级 + 微信服务通知异步"的实时性不足。

**连接与鉴权**：

- **连接路径**：`WS /api/ws/{user_id}?token=<JWT>`
- **鉴权方式**：连接握手时通过 query 参数 `token` 传入 JWT；服务端从数据库校验 user_id 与 token 一致性后接受连接
- **多连接支持**：同一用户允许同时建立多个连接（PC + 手机 + 眼镜同时在线）

**连接池设计**：

```python
# 用户连接池：user_id -> Set[WebSocket]
_user_connections: Dict[int, Set[WebSocket]] = {}

# 项目用户映射：project_id -> Set[user_id]
_project_users: Dict[int, Set[int]] = {}
```

- `_register_connection`：连接建立时注册到用户池 + 项目池
- `_unregister_connection`：断开时从用户池移除（项目池保留 user_id，因为可能还有其他连接）
- 死连接清理：`_send_ws` 失败的连接会被收集并批量移除

**广播工具函数**：

| 函数 | 签名 | 行为 |
|---|---|---|
| `broadcast_to_user` | `(user_id, message) -> int` | 向指定用户的所有连接推送，返回成功数 |
| `broadcast_to_project` | `(project_id, message) -> int` | 向项目内所有在线用户推送 |

**消息格式**：

```json
{
  "event_type": "task_assigned | hazard_detected | document_approved | work_record_submitted | inspection_hazard | ...",
  "data": { ... },
  "timestamp": "2026-07-18T10:30:00Z"
}
```

**推送场景清单**（11 处调用 `push_realtime`）：

| 模块 | 场景 | event_type |
|---|---|---|
| document | 文书审批通过 | `document_approved` |
| document | 文书驳回 | `document_rejected` |
| document | 文书归档 | `document_archived` |
| hazard | 隐患提报 | `hazard_reported` |
| hazard | 隐患整改通知 | `hazard_notified` |
| hazard | 隐患复查结果 | `hazard_recheck` |
| inspection | 巡检启动 | `inspection_started` |
| inspection | 巡检停止 | `inspection_stopped` |
| inspection | 巡检命中隐患 | `inspection_hazard` |
| task | 派单分配 | `task_assigned` |
| task | 派单完成/取消 | `task_updated` |
| work_record | 工作记录提交/审批/归档 | `work_record_updated` |

### 3.10 微信服务通知架构

微信服务通知用于在用户离线时将业务事件（派单、整改、审批结果、巡检告警）通过微信订阅消息推送到用户微信，作为 WebSocket 实时推送的补充通道。

**技术实现**：

| 组件 | 文件 | 职责 |
|---|---|---|
| 数据模型 | `models/wechat_subscription.py` `WechatSubscription` | 存储用户 openid 与已订阅模板 |
| 路由 | `routers/wechat_notice.py` | 4 个接口：send / subscribe / templates / status |
| 服务 | `services/wechat_notice.py` | access_token 缓存 + subscribeMessage.send |
| 依赖 | httpx | 异步调用微信服务端 API |

**access_token 缓存策略**：

```python
# 内存缓存：(appid, secret) -> (token, expire_ts)
_access_token_cache: dict[tuple, tuple[str, float]] = {}

async def get_access_token() -> str:
    # 1. 命中缓存且剩余有效期 > 5 分钟 -> 直接返回
    # 2. 否则调用 GET /cgi-bin/token?grant_type=client_credential&appid=...&secret=...
    # 3. 缓存新 token，过期时间 = now + expires_in（默认 7200 秒）
    # 4. 提前 5 分钟刷新，避免边界过期
```

**subscribeMessage.send 调用流程**：

1. 业务模块调用 `push_to_wechat(user_id, template_id, data, page)`
2. 服务层查 `WechatSubscription` 表获取用户 openid
3. 调用 `get_access_token()` 获取 access_token
4. `POST /cgi-bin/message/subscribe/send` 发送订阅消息
5. 失败时记录日志，不阻塞主业务

**API 清单**：

| 接口 | 路径 | 行为 |
|---|---|---|
| 发送通知 | `POST /api/wechat/notice/send` | 管理员调用，向指定用户发送订阅消息 |
| 订阅通知 | `POST /api/wechat/notice/subscribe` | 用户授权订阅某模板 |
| 模板列表 | `GET /api/wechat/notice/templates` | 列出可用模板 |
| 订阅状态 | `GET /api/wechat/notice/status` | 查询当前用户订阅状态 |

**安全控制**：
- access_token 仅在服务端获取与缓存，不下发客户端
- AppSecret 仅通过环境变量 `WECHAT_APP_SECRET` 配置
- 订阅消息必须用户主动授权后才能发送（微信平台限制）
- 发送频率受微信平台配额限制，超出时降级为系统内通知

## 六、微信小程序端技术方案

### 6.1 技术选型与目录

微信小程序端采用原生小程序 + TypeScript，独立目录为 `wechat-miniprogram/`，避免将 Vue/Element Plus 代码直接迁移到不兼容的小程序运行时。建议目录：

```
wechat-miniprogram/
├── app.ts / app.json / app.wxss
├── project.config.json
├── miniprogram/
│   ├── pages/                 # 登录、工作台、智能体、采集、通话、待办、隐患
│   ├── components/            # 媒体预览、录音按钮、通话控制条
│   ├── services/              # request/upload/socket/rtc/auth/agent
│   ├── stores/                # JWT、用户、项目、待上传队列
│   ├── types/                 # API、媒体、RTC 类型
│   └── utils/                 # 权限、幂等键、错误映射
└── README.md
```

### 6.2 登录与现有账号绑定

```
小程序 wx.login 获取一次性 code
  → POST /api/miniprogram/auth/login
  → 后端调用微信 code2Session（AppSecret 仅服务端持有）
  → 已绑定：签发监理通 JWT
  → 未绑定：返回 bind_token
  → 用户输入现有监理通账号密码
  → POST /api/miniprogram/auth/bind
  → 校验成功后绑定 openid/unionid 并签发 JWT
```

JWT 继续沿用现有 `Authorization: Bearer <token>` 机制。数据库需要新增微信身份绑定表，避免将 `openid` 直接混入通用用户字段：

| 表 | 关键字段 |
|---|---|
| `wechat_user_bindings` | `id`、`user_id`、`openid`（唯一）、`unionid`（可空）、`created_at`、`last_login_at` |

### 6.3 拍照、录像和录音

- **拍照/录像**：页面通过原生相机组件创建相机上下文，调用拍照/录像能力；确认后使用上传 API 发送 `multipart/form-data`
- **相册导入**：通过媒体选择 API 选择图片/视频，上传前校验类型、大小、时长
- **录音**：通过全局录音管理器录制 MP3/AAC，完成后上传 `/api/local/stt/transcribe`
- **智能体**：STT 文本发送 `/api/local/voice-command` 或 `/api/local/llm/chat`，回答以文字展示，并可由小程序音频能力播放服务端生成的 TTS
- **可信取证**：客户端预览水印仅用于反馈；最终水印时间、人员、项目、位置及 SHA256 均由后端生成并入库，来源标记 `miniprogram`
- **失败重试**：本地只保存临时文件路径和待上传元数据，每次创建业务记录携带 `Idempotency-Key`

建议新增统一媒体接口，避免小程序绕过影像台账：

| 接口 | 用途 |
|---|---|
| `POST /api/media/images` | 上传图片、生成水印/哈希/影像记录，可选触发 VLM |
| `POST /api/media/videos` | 上传视频并关联工作记录/隐患/整改 |
| `POST /api/media/audio/transcribe` | 上传录音并转写，内部复用 STT 服务 |
| `GET /api/media/{id}` | 按权限读取媒体元数据和短期访问地址 |

### 6.4 实时音视频架构

微信小程序实时音视频使用小程序支持的 RTC 推拉流组件/官方支持的 RTC SDK。不得在小程序中尝试直接复用浏览器 WebRTC 页面，也不得由 FastAPI 转发音视频媒体流。

```
小程序 A ──HTTPS──► FastAPI：创建/接受/结束会话、获取短期凭证
小程序 A ◄──WSS──► FastAPI：邀请、振铃、接听、拒绝、挂断信令
小程序 A ◄════ RTC 加密媒体 ════► 小程序 B
                      │
                 RTC 云服务
```

后端新增 `rtc` 服务与 `call_sessions` / `call_participants` 表：

| 接口 | 用途 |
|---|---|
| `POST /api/rtc/calls` | 校验同项目成员关系，创建呼叫并返回短期入房凭证 |
| `POST /api/rtc/calls/{id}/accept` | 接听并返回接收人的短期入房凭证 |
| `POST /api/rtc/calls/{id}/reject` | 拒绝呼叫 |
| `POST /api/rtc/calls/{id}/end` | 结束通话，幂等更新结束原因 |
| `GET /api/rtc/calls/{id}` | 查询会话及成员状态 |
| `WS /api/rtc/signaling?token=...` | 在线呼叫信令；连接时校验 JWT |

`call_sessions` 至少保存项目、发起人、媒体类型、RTC 房间 ID、状态、创建/接通/结束时间和结束原因；`call_participants` 保存成员、加入/离开时间及状态。RTC Secret 仅在服务端用于签发短期凭证，凭证必须绑定用户、房间和过期时间。

默认不录制媒体。如启用云端录制，需独立的用户同意、存储周期、访问控制、审计和删除策略。

### 6.5 权限、隐私和平台配置

- 配置小程序 request/uploadFile/downloadFile/socket 合法域名，全部使用已备案 HTTPS/WSS 域名
- 在用户主动点击拍摄、录音或通话时申请摄像头/麦克风权限；拒绝后提供设置入口和非媒体降级路径
- 配置小程序隐私保护指引，说明摄像头、麦克风、相册、位置、文件及通话用途
- AppID、AppSecret、RTC SDKAppID/Secret 等按环境管理，Secret 不进入小程序包或 Git
- 服务端校验项目数据隔离、媒体归属和 RTC 成员资格；小程序前端权限显隐不能替代后端 RBAC
- 微信服务通知仅发送用户已授权的业务提醒；实时来电优先通过 WSS，离线时用服务通知提示回到小程序

### 8.2 关键模型说明

- **User（用户）**：四种角色用户，通过 RBAC 矩阵控制权限，区分专监与总监层级。
- **Project（项目）**：业务数据核心归属维度，工作记录、文书、隐患等均关联项目。
- **WorkRecord（工作记录）**：巡视/验收/见证/旁站四类工作记录，五种状态流转；含 `reject_reason`/`approved_by`/`approved_at` 审批字段。
- **Document（监理文书）**：九类监理文书，五种状态流转，部分类型需总监签发；含 `signed_pdf_path`/`signed_by`/`signed_at` 签章字段。
- **Hazard（隐患）**：六种状态流转，存储 VLM 识别返回的隐患信息；含 `matched_regulations_json` 自动匹配的规范条款。
- **RectificationRecord（整改记录）**：关联隐患与整改通知单，记录整改与复查情况。
- **ImageRecord（影像记录）**：存储 SHA256 哈希值校验图片完整性，用于防篡改溯源。
- **TaskAssignment（派单）**：六种状态、四种优先级、八种类别的派单任务管理。
- **KGEntity / KGRelation（知识图谱）**：知识图谱实体与关系，支撑规范条款检索与推理。
- **RegulationChunk（规范向量块）**：建筑规范向量化分块，用于知识检索与 RAG 问答。
- **WechatUserBinding（微信绑定）**：微信用户标识与现有监理通账号的一对一绑定关系。
- **MediaRecord（媒体记录）**：统一保存图片、视频、录音的来源、哈希、业务关联和访问策略。
- **CallSession / CallParticipant（通话）**：保存 RTC 房间、会话状态、参与者和审计时间，不默认保存媒体内容。
- **Signature（电子签章）**：存储签章图片路径、签章人、角色、激活状态，签署时校验 bcrypt 密码并记录 SHA256 留痕。
- **InspectionSession（巡检会话）**：云端 AI 巡检闭环核心模型，记录项目、巡检人、状态（active/stopped）、采集频率、累计采集/命中数、最近采集/命中时间。
- **AcceptanceTemplate（验收流程模板）**：PC 端维护的验收流程模板，含检查项、管控要点、规范依据、检查方法。
- **Archive（台账归档）**：批量台账导出/归档记录，含导出类型、文件路径、操作人、归档时间。
- **VideoRecord（视频记录）**：视频水印与元数据记录，关联工作记录/隐患/整改。
- **WechatSubscription（微信订阅）**：用户 openid 与已订阅模板的绑定关系，支撑微信服务通知推送。

完整字段定义见开发文档数据模型说明。

### 8.2.1 云端 AI 实时巡检模式

云端 AI 实时巡检模式已从原"单张拍照识别"扩展为完整闭环，由 `InspectionSession` 模型 + `routers/inspection.py`（6 接口）+ `services/inspection_service.py` + `services/regulation_matcher.py` 协同实现。

**巡检会话 API（已实现）**：

| 接口 | 路径 | 行为 |
|---|---|---|
| 启动巡检 | `POST /api/inspection/start` | 创建 InspectionSession（status=active），同用户同时只允许一个活动会话；入参 `project_id`、`frequency_seconds`（默认 5） |
| 停止巡检 | `POST /api/inspection/{session_id}/stop` | 置为 stopped，记录 stopped_at；幂等 |
| 查询活动会话 | `GET /api/inspection/active` | 返回当前用户 active 会话，无则返回 null |
| 巡检统计 | `GET /api/inspection/{session_id}/stats` | 返回 total_captures/total_hazards/last_capture_at/last_hazard_at |
| 历史会话 | `GET /api/inspection/history` | 分页返回历史会话列表 |
| 采集识别 | `POST /api/inspection/{session_id}/capture` | 上传一张图片，触发完整识别闭环 |

**采集识别闭环（`capture` 接口内部）**：

```
1. 接收图片 -> assert_valid_image 校验
2. apply_watermark_to_image 叠加项目/时间/人员/位置水印
3. 保存到 uploads/ -> 写入 ImageRecord（SHA256）
4. ai_client.recognize_hazard 调用 VLM 识别
5. 若命中隐患：
   ├─ 创建 Hazard 记录（status=reported）
   ├─ regulation_matcher.match_regulations 自动匹配规范条款
   │   ├─ 隐患类别映射到 REGULATION_CATEGORIES 分类
   │   ├─ 在对应分类下用关键词匹配 RegulationChunk
   │   ├─ 不足时回退到全文搜索
   │   └─ 返回 [{chunk_id, content, category, relevance_score}]
   ├─ 写入 Hazard.matched_regulations_json（JSON）
   ├─ push_realtime 向巡检人推送 inspection_hazard 事件
   └─ broadcast_to_project 向项目内 PC 端推送
6. 更新 InspectionSession 计数与时间戳
7. 返回识别结果与隐患 ID
```

**自动匹配规范实现要点**（`services/regulation_matcher.py`）：

- 隐患类别（risk_category）映射到规范库分类，例如 `"安全帽" -> ["安全管理规范", "安全监理用表"]`、`"脚手架" -> ["施工技术规范", "安全管理规范"]`
- 在对应分类下用关键词匹配 `RegulationChunk.content`
- 匹配数不足时回退到所有分类的全文搜索
- 返回结构化结果，含 `relevance_score` 排序
- 使用同步 SQLAlchemy 引擎（pymysql），避免与 async 事件循环冲突

**眼镜端联动**：眼镜端 `InspectionActivity` 通过 `InspectionBus`（单例 `object`）共享当前会话 ID，启动后 `CameraManager` 按 `frequency_seconds` 周期采集，`ImageUploader` 上传至 `capture` 接口，命中隐患时由 `CommandHandler` 下发 `speak_urgent` + `vibrate` 指令。

| 降级方案 | 无（本地 Ollama 不支持视觉任务） |
| 使用场景 | 拍照隐患识别、图片内容分析 |

### 9.3 LLM 调用策略（三级降级）

```
请求发起

   ▼

└────────────┬────────────────────┘
             │ 失败/超时
             ▼
┌─────────────────────────────────┐

│ OpenAI 兼容接口                 │

             │ 失败
             ▼
┌─────────────────────────────────┐
```

**降级原则**：
1. 本地优先，降低外部依赖与调用成本

3. 每一级失败后自动切换下一级，记录日志便于排查

### 10.2 RBAC 权限控制

- **四种业务角色**：总监理工程师、总监代表、专业监理工程师、监理员；`admin` 为超级管理员账号
- **权限矩阵**：`ROLE_PERMISSIONS` 定义角色可访问的功能集合
- **后端校验**：基于依赖注入的权限校验，路由级别拦截
- **前端校验**：路由守卫 + 组件级 v-if 控制元素显隐
- **总监专属**：`NEED_APPROVAL_TYPES` 文书类型必须由总监签发

权限体系详见 [1-需求RPD文档.md](./1-需求RPD文档.md#2-角色与权限)。

### 10.3 水印防篡改

```
┌──────────────┐   ┌──────────────┐   ┌──────────────────────┐
│ 原始图片/文书 │──►│  水印服务    │──►│ 叠加水印的输出文件    │

                   │  天气 API    │   └──────────────────────┘
                   │  集成        │
                   └──────────────┘
```

- 导出图片/文书自动叠加水印
- 水印内容含项目、时间、天气、操作人，用于防伪溯源
- 天气信息通过外部天气 API 实时获取

### 10.4 影像哈希防篡改

- `ImageRecord` 模型存储图片 SHA256 哈希值
- 图片校验时重新计算哈希并比对，确保图片未被篡改
- 适用于取证、责任追溯场景

### 10.5 CORS 与网络安全

- `allow_origins=["*"]` 仅用于本地开发
- 生产环境按 Web 端域名收紧 CORS，并配置微信小程序合法域名
- 所有通信强制 HTTPS

### 10.6 性能优化

- **异步架构**：FastAPI + SQLAlchemy 2.0 异步 ORM + aiomysql，全链路非阻塞
- **本地 AI 优先**：Ollama/faster-whisper 本地部署，降低网络往返延迟
- **int8 量化**：faster-whisper 使用 int8 量化降低 CPU 推理开销
- **VAD 过滤**：语音识别前裁剪静音片段，减少推理计算量
- **连接复用**：数据库连接池、HTTP 客户端连接复用

### 11.2 眼镜端部署

- **分发方式**：在 Rokid Glass App 智能体商店上架
- **安装方式**：用户在眼镜端商店搜索"监理通"安装
- **运行环境**：Rokid Glass 操作系统
- **网络要求**：眼镜需连接 WiFi 或 5G 网络
- **更新机制**：通过智能体商店推送更新
- **无需后端部署**：眼镜端为客户端，无需独立服务端

### 11.3 手机浏览器端部署

- **部署方式**：Web 前端构建产物（静态资源）部署至 Nginx/CDN
- **访问方式**：手机浏览器输入 SaaS 域名访问
- **响应式适配**：适配不同手机屏幕尺寸
- **语音能力**：优先使用浏览器原生 Web Speech API，不可用时降级至后端 faster-whisper
- **拍照能力**：通过浏览器调用手机摄像头，或从相册导入图片

### 11.4 微信小程序端部署

- **发布方式**：微信开发者工具构建、体验版联调、提交审核后发布
- **平台配置**：AppID、类目、隐私保护指引、用户隐私接口、request/upload/download/socket 合法域名
- **媒体能力**：按微信平台要求申请并开通实时音视频相关类目/组件权限，接入选定 RTC 服务
- **后端依赖**：配置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`、RTC AppID/Secret，提供公网 HTTPS/WSS
- **环境隔离**：开发版、体验版、正式版使用不同后端环境和 RTC 配置
- **审核材料**：准备账号绑定说明、摄像头/麦克风用途说明、隐私政策、测试账号和完整功能路径

### 11.5 PC Web SaaS 端部署

- **部署方式**：与手机浏览器端共用前端构建产物（响应式适配 PC 屏幕），或独立部署 PC 版
- **访问方式**：PC 浏览器输入 SaaS 域名访问
- **核心功能**：
  - 全部业务功能管理（项目、工作记录、文书、隐患、派单等）
  - 系统设置与用户管理
  - 眼镜模拟器（在 PC 上模拟眼镜端交互，用于测试与演示）
  - 智能监理助手（基于 LLM 的对话式助手）
  - 数据导出（PDF/Excel）

### 11.6 后端部署

- **应用进程**：FastAPI 通过 Uvicorn/Gunicorn 部署，建议多 Worker
- **反向代理**：Nginx 反向代理 + HTTPS 终止
- **数据库**：MySQL 8.0 独立部署或托管服务
- **本地 AI 服务**：
  - Ollama 进程独立运行，暴露本地端口供后端调用
  - faster-whisper 作为后端进程内的库调用
- **文件存储**：本地 `uploads/`、`exports/` 目录，建议挂载独立数据盘
- **外部依赖**：AI Center API（华工 VLM、降级 LLM）、天气 API（水印服务）
- **小程序依赖**：微信登录/服务通知接口、RTC 服务；公网入口需同时支持 HTTPS 与 WSS

### 13.4 全栈协同流程示例（云端 AI 巡检 + 多端联动）

```
1. 眼镜端 MenuActivity 选择"AI 巡检"
   └─> InspectionActivity 启动 -> POST /api/inspection/start
        └─> 后端创建 InspectionSession(active)
        └─> InspectionBus 记录 session_id

2. CameraManager 按 frequency_seconds 周期采集
   └─> ImageUploader 上传至 POST /api/inspection/{id}/capture
        ├─ 后端叠加水印 + SHA256 入库
        ├─ ai_client.recognize_hazard 调用 VLM
        ├─ 若命中：
        │   ├─ 创建 Hazard(reported) + matched_regulations_json
        │   ├─ push_realtime -> 眼镜端 InspectionActivity（inspection_hazard）
        │   ├─ broadcast_to_project -> PC 端 InspectionDashboard（hazard_detected）
        │   └─ push_to_wechat -> 巡检人微信（订阅消息）
        └─ 返回识别结果

3. 眼镜端 CommandHandler 收到 inspection_hazard
   └─> 下发 speak_urgent + vibrate 指令
   └─> 跳转 HazardDetailActivity 展示隐患 + 规范条款

4. PC 端 InspectionDashboard 实时刷新
   └─> WebSocket 收到 hazard_detected
   └─> 更新趋势图与饼图

5. 手机浏览器端（mobile-h5）查看巡检历史
   └─> GET /api/inspection/history
   └─> 离线时缓存请求，联网后重放

6. 巡检结束 -> POST /api/inspection/{id}/stop
   └─> 眼镜端 InspectionBus 清空 session_id
   └─> 后端 InspectionSession(status=stopped)
```
