# 监理通 - 项目开发文档

> 建筑工程监理智能体系统（品牌名"监理通"）
> 基于"眼镜端 + 手机浏览器端 + 微信小程序端 + PC Web SaaS 端"四端协同部署模式
> 文档版本：全栈实现完成版
> 更新日期：2026-07-18
> 说明：本版反映全栈补齐实现，新增 mobile-h5 独立工程、glasses-app 业务页面与基础能力层、后端 5 个新路由模块（signature/inspection/ws/acceptance-template/wechat-notice）与 6 个新数据模型，并补充对应的对接指南。

## 四端部署总览

监理通采用四端协同部署模式，统一由 `cloud-backend` 提供业务、认证、AI、媒体管理与音视频信令服务：

| 端 | 业务定位 | 形态 | 项目目录 | 访问方式 | 核心场景 |
|---|---|---|---|---|---|
| 眼镜端 | **现场零手持作业端** | Rokid Glass App 智能体（Android Kotlin + CXR-S） | `glasses-app/` | 在 Rokid 智能体商店上架，AI 眼镜直接使用 | 现场巡视、拍照取证、隐患识别、语音播报、AI 自动巡检、签章查看 |
| 手机浏览器端 | **便携经办端** | 独立 PWA Web 应用（Vue 3.5 + Vant 4） | `mobile-h5/`（端口 5174） | 手机浏览器访问，使用手机麦克风/扬声器或蓝牙耳机 | 现场语音交互、移动办公、轻量录入、隐患整改复查、离线队列 |
| 微信小程序端 | **微信生态移动协作端** | 原生微信小程序 | `wechat-miniprogram/` | 微信搜索/扫码/分享进入，调用手机摄像头和麦克风 | 拍照录像、录音问答、隐患识别、整改复查、音视频通话、服务通知 |
| PC Web SaaS 端 | **后台管控归档端** | PC Web 管理后台（Vue 3 + TS + Element Plus） | `web-admin/`（端口 3000） | PC 浏览器访问 SaaS 管理后台，保留眼镜模拟器 | 文书审批、电子签章、台账管理、规范库维护、验收流程模板配置、巡检可视化、模拟器调试 |

四端共享同一套后端 API、数据库与 AI 服务，通过 RBAC 分权分域实现差异化功能。小程序音视频媒体不经过 FastAPI 转发，由 RTC 服务承载；FastAPI 只负责房间、短期凭证、信令和审计。

**全栈实现完成版新增项目**：
- `mobile-h5/`：手机浏览器端独立 PWA 工程（原为 web-admin 移动适配，现拆分为独立项目）
- `glasses-app/`：眼镜端 Kotlin 工程大幅补齐，新增网络/相机/语音/数据 4 大基础能力层与 9 大业务页面

#### AI 客户端调用策略（`ai_client.py`）

### 6.1 智能体上架流程

| action | 参数 | 行为 |

| `rtc_camera` | `enabled` | 企业版开关摄像头 |

当前 CXR-S 版本以 topic 传递应用消息：`gdjl.command` 接收 JSON 指令，`gdjl.key_event` 接收宿主转发的按键事件，`gdjl.report` 上报业务消息。不要使用旧示例中的 `getInstance`、`setOnKeyListener` 或 `sendCommand`，这些方法不在当前依赖版本中。

### 6.3 API 对接

时不影响四端系统、商业版眼镜 APK 或企业版眼镜 APK 上线。

### 7.1 初始化与页面结构

微信小程序采用原生 TypeScript，根目录固定为 `wechat-miniprogram/`。当前已经实现以下页面：

| 页面 | 路径 | 说明 |
|---|---|---|
| 登录/绑定 | `pages/login/index` | 微信登录、现有监理通账号绑定 |
| 工作台 | `pages/home/index` | 待办、快捷采集、智能体入口、联系人 |
| 智能体 | `pages/agent/index` | 文字输入、录音转写、回答展示与播放 |
| 现场采集 | `pages/capture/index` | 拍照、录像、相册选择、预览与上传 |
| 工作记录 | `pages/work/index` | 巡视、验收、见证、旁站创建与流转 |
| 隐患列表/处置 | `pages/hazards/index` | 识别结果、整改单、整改影像、复查 |
| 通讯录 | `pages/contacts/index` | 仅显示同项目且有权通话的成员 |
| 来电/通话 | `pages/call/index` | 呼入、呼出、音频/视频控制及弱网状态 |
| 待办 | `pages/todo/index` | 派单、整改和审批结果 |

小程序端已独立封装 `request`、`upload`、`uploadQueue`、`signaling`、`rtc`、`auth`、`session` 服务。业务页面不直接持有 AppSecret、RTC Secret 或模型 Token。

派单、隐患和整改详情页支持生成小程序分享卡片。分享路径只携带不敏感的业务资源 ID/短期分享码，接收方打开后必须完成登录并由后端重新校验项目成员关系与 RBAC。

### 7.2 微信登录与账号绑定

1. 小程序调用 `wx.login` 获取一次性 `code`
2. 调用 `POST /api/miniprogram/auth/login`
3. 后端用 AppID/AppSecret 调用微信服务端换取 `openid`/`unionid`
4. 已绑定用户直接返回系统 JWT；未绑定返回短期 `bind_token`
5. 用户输入现有监理通账号、密码和角色，调用 `POST /api/miniprogram/auth/bind`
6. 后端复用现有密码与角色校验，创建 `wechat_user_bindings` 并签发 JWT

禁止用微信昵称或手机号自动创建高权限监理账号。账号绑定、解绑和换绑必须留下审计记录。

### 7.3 HTTP、上传与幂等

- API 根地址按开发版/体验版/正式版配置，正式环境必须为已备案 HTTPS 合法域名
- `wx.request` 自动附加 `Authorization: Bearer <JWT>`；401 时清理会话并返回登录页
- `wx.uploadFile` 上传图片、视频、录音；表单带 `source=miniprogram`、项目、业务类型和关联 ID
- 新建媒体、隐患、工作记录时生成 UUID 作为 `Idempotency-Key`，后端保存并去重
- 上传失败写入待同步队列，临时文件失效前提示用户重试；上传成功后删除本地队列项
- 服务端校验 MIME、扩展名、文件头、大小、时长和项目归属，不信任客户端元数据

### 7.4 拍照、录像与智能体语音

**拍照/录像**：

1. 用户点击拍照或录像，页面此时才申请摄像头权限
2. 使用原生相机上下文拍照或开始/停止录像
3. 本地预览，用户确认后调用 `/api/media/images` 或 `/api/media/videos`
4. 图片由后端叠加可信水印、计算 SHA256、写入影像台账；视频保存元数据并绑定业务记录
5. 需要 AI 分析时，图片上传响应或后续接口触发 VLM，不直接把模型 Token 下发小程序

**录音调用监理智能体**：

1. 用户按住说话或点击开始录音，使用全局录音管理器采集 MP3/AAC
2. 停止后上传 `/api/media/audio/transcribe`
3. 后端复用 faster-whisper 返回文本
4. 文本发送 `/api/local/voice-command`（业务指令）或 `/api/local/llm/chat`（自由问答）
5. 小程序显示回答；需要播报时播放后端 TTS 音频或经审核可用的客户端语音能力

摄像头、麦克风、相册和位置权限被拒绝时，页面必须展示用途、设置入口和可用的降级功能。

### 7.5 实时音视频通话

微信小程序的实时音视频必须接入小程序支持的 RTC 推拉流组件或官方支持的 RTC SDK。浏览器 `getUserMedia`/WebRTC 代码不能直接复用，FastAPI 也不承担媒体转发。

**呼叫流程**：

1. `POST /api/rtc/calls` 提交被叫用户和 `audio`/`video`
2. 后端校验双方同项目关系和 RBAC，生成不可预测的房间 ID、会话记录及短期 RTC 凭证
3. WSS 信令发送 `incoming_call`；离线用户可收到已授权的微信服务通知
4. 被叫调用 `accept` 或 `reject`；接听后获取自己的短期凭证进入同一 RTC 房间
5. 小程序通话页管理麦克风、摄像头、前后摄像头、扬声器和远端画面
6. 任一方调用 `end`，或服务端检测超时/掉线，幂等结束会话并写入审计

**信令消息**：

| type | 说明 |
|---|---|
| `incoming_call` | 新来电，含会话 ID、主叫、媒体类型，不含 RTC Secret |
| `call_ringing` | 被叫在线并振铃 |
| `call_accepted` | 被叫接听，双方进入房间 |
| `call_rejected` | 被叫拒绝 |
| `call_ended` | 主动挂断、超时、网络失败或服务端终止 |
| `participant_state` | 成员加入、离开、静音或摄像头状态 |

RTC 凭证只由后端生成，建议 5～15 分钟有效；重连时后端校验原会话后重新签发。默认不录制通话，若启用云录制必须在入房前明确告知所有参与者并获得同意。

### 7.6 微信平台配置与发布

1. 配置业务类目、隐私保护指引和摄像头/麦克风等用户隐私接口声明
2. 配置 request、uploadFile、downloadFile、socket 合法域名
3. 按微信平台要求申请实时音视频组件/接口权限，并完成 RTC 服务开通
4. 使用真机验证拍照、录像、录音、前后台切换、弱网、来电和双端通话
5. 提交体验版给业务方验收，准备审核测试账号、账号绑定说明和完整操作路径
6. 审核通过后发布；生产 AppSecret、RTC Secret 只在服务端环境变量中配置

### 7.7 最低测试清单

- 登录 code 只能使用一次，未绑定/已绑定/解绑/Token 过期路径正确
- 摄像头、麦克风、相册授权允许与拒绝路径均可用
- 图片水印、哈希、来源、项目和业务关联正确
- 视频/录音格式、大小、时长超限时前后端均能阻止
- STT → 指令/问答 → 回答展示链路可用
- 音频/视频呼叫、接听、拒绝、挂断、静音、摄像头切换、断网重连可用
- 非同项目成员、伪造会话 ID、过期 RTC 凭证和无效 JWT 均被拒绝
- 重试不产生重复媒体、隐患或工作记录

## 九、核心业务流程开发指引

本章对应 RPD 第 14 章"业务流程总览"中的 5 个核心业务流程，给出具体的开发对接说明。

### 9.1 流程1：现场影像采集开发指引

**多渠道采集实现**：

| 渠道 | 实现位置 | 关键接口 |
| 眼镜端语音触发拍摄 | CXR-S 宿主相机能力（需 Rokid 真机联调） | 宿主采集后调用 `POST /api/media/images` |
| 眼镜端语音触发拍摄 | 商业版 CameraX / 企业版 Glass Media Service | `CameraManager` 统一水印后调用 `POST /api/media/images` |
| 手机端拍照/相册/微信导入 | `web-admin/src/views/CameraSimulator.vue` | 浏览器 `getUserMedia` + `<input type="file" accept="image/*" multiple>` |
| 微信小程序端拍照/录像/相册 | `wechat-miniprogram/miniprogram/pages/capture/` | 原生相机/媒体选择 + `POST /api/media/images` 或 `/videos` |
| PC 端批量导入 | `web-admin/src/views/CameraSimulator.vue` | 文件夹批量选择 + `POST /api/watermark/batch-upload` |

**语音口述部位**：眼镜端通过 `voice_command` 接口将口述文本送后端 LLM 解析为"楼栋/楼层/部位"字段，自动绑定至影像记录。

**后端接口**（`routers/wechat_notice.py`，4 接口）：

| 接口 | 路径 | 行为 |
|---|---|---|
| 发送通知 | `POST /api/wechat/notice/send` | 管理员调用，向指定用户发送订阅消息 |

- 催办：通知被指派人

- 订阅消息必须用户主动授权后才能发送

- 后端在业务事件触发时自动调用 `push_to_wechat`

## 十、开发规范

### 10.1 代码风格

- **后端（Python）**：
  - 遵循 PEP 8，行宽 120
  - 类型注解：函数参数与返回值必须标注（`from typing import Optional`）
  - 异步优先：所有 DB/HTTP 操作使用 `async/await`
  - 配置统一走 `app/config.py` 的 `Settings`，禁止散落硬编码
  - 路由文件只做参数校验与编排，业务逻辑放 `services/`
- **前端（TypeScript/Vue）**：
  - `<script setup lang="ts">` 组合式 API
  - 禁止 `any` 滥用，接口返回定义类型
  - API 调用统一走 `src/api/index.ts`，组件内不直接 `axios`
  - 状态统一放 Pinia store
- **眼镜端（Kotlin）**：
  - 遵循 Android 官方 Kotlin 风格指南
  - 指令处理集中在 `command/` 包，新增 action 在 `CommandHandler.dispatch` 注册
- **微信小程序端（TypeScript）**：
  - 页面只负责交互，HTTP/上传/WSS/RTC 统一放在 `services/`
  - 不使用 `any` 承接 API/信令数据；所有事件定义可辨识联合类型
  - 不在代码、配置文件或日志中出现 AppSecret、RTC Secret、AI Token
  - 摄像头、麦克风和位置能力仅在用户主动操作时调用

### 10.2 Git 分支

| 分支 | 用途 |
|---|---|
| `main` | 生产稳定分支，仅接受合并/Tag |
| `develop` | 集成测试分支 |
| `feature/<模块>-<简述>` | 功能开发（如 `feature/hazard-recheck`） |
| `fix/<简述>` | 缺陷修复 |
| `hotfix/<简述>` | 生产紧急修复 |

提交信息约定：`<type>(<scope>): <subject>`，type 取 `feat` / `fix` / `docs` / `refactor` / `chore` / `perf`。

### 10.3 API 设计规范

- 统一前缀 `/api`，RESTful 风格
- 认证接口除外，所有接口需 `Authorization: Bearer <JWT>`
- 权限校验使用 `Depends(require_permission("xxx"))` 或 `require_role(...)`
- 返回结构：
  - 成功：直接返回数据对象或数组
  - 失败：FastAPI `HTTPException`，`detail` 为中文可读信息
  - 列表：`{ "items": [...], "total": N }` 或直接数组
- 文件上传：`multipart/form-data`；导出：返回文件流或 `/exports` 静态 URL
- 媒体/业务创建接口接受 `Idempotency-Key`，重复请求返回同一资源
- WSS 连接必须通过 `Authorization: Bearer <JWT>` 请求头鉴权（禁止把 JWT 放入会被访问日志记录的查询参数）；RTC 入房凭证必须短期有效且绑定用户与房间
- 状态码：200 成功 / 400 参数错误 / 401 未认证 / 403 无权限 / 404 不存在 / 503 依赖服务不可用

### 11.4 模型调用设置与密钥安全

PC 管理端“系统设置 → 模型调用设置”统一管理 `llm`、`tts`、`stt`、`vlm`
四类模型。管理接口为：

- `GET /api/model-settings`：查询四类配置，只返回 `api_key_masked=********`
  和 `has_api_key`，不返回密钥或密文；
- `PUT /api/model-settings/{model_type}`：更新提供商、URL、Model ID、启停状态
  和可选密钥；提交 `********` 或不提交 `api_key` 时保留原密钥；
- `POST /api/model-settings/{model_type}/reset`：恢复服务端环境变量定义的默认配置。

接口仅允许拥有 `settings` 权限的用户访问。四类默认配置会在首次启动时写入
`model_configurations` 表，后续更新同样写入该表，因此进程重启不会清空。
后端始终按 `cloud-backend/.env` 的绝对路径加载默认值和加密密钥，不依赖
启动命令的当前目录。真实 API Key 只存在于部署环境变量
或 `model_configurations.api_key_encrypted` 密文字段，数据库密文使用
`MODEL_CONFIG_ENCRYPTION_KEY` 派生的 Fernet 密钥加密。生产环境必须使用独立、
至少 32 位的随机加密密钥；更换该变量前必须先完成密文迁移，否则旧配置无法解密。
`.env` 文件权限应设为 `600`，不得提交代码仓库，也不得开启包含 SQL 参数的数据库日志。

运行时调用统一走 `services/model_gateway.py`：

- LLM：OpenAI 兼容 `/chat/completions`；
- 华工 VLLM：按模型文档使用 `invoke-upload`、`org_id`、`environment` 与图片文件；
- 阿里 CosyVoice：根据工作空间域名调用 HTTP `SpeechSynthesizer`。CosyVoice 3.5
  不提供系统音色，必须在设置页填写已创建的克隆/设计音色 ID；
- 阿里 Paraformer Realtime：根据工作空间域名派生 WSS `/api-ws/v1/inference`，
  后端把 Web/眼镜/小程序音频转为单声道 16 kHz WAV，再按 `run-task`、
  二进制音频、`finish-task` 协议转写；
- 其他 STT/TTS 供应商：使用 OpenAI 兼容 `/audio/transcriptions` 和 `/audio/speech`。

前端、眼镜和小程序均不得直连模型供应商或持有供应商密钥。

### 12.2 前端启动失败

| 现象 | 排查 |
|---|---|
| `npm install` 失败 | 切换镜像 `npm config set registry https://registry.npmmirror.com` |
| 接口 404 / 跨域 | 确认后端已启动；检查 `vite.config.ts` 代理目标为 `http://localhost:8000` |
| 登录后立即跳回登录页 | 检查后端 `SECRET_KEY` 是否被改动导致 JWT 失效；清 `localStorage` 重试 |
| `vue-tsc` 类型报错阻断构建 | 修复类型错误，或临时 `npm run build` 前确认无 TS 错误 |

### 12.3 AI 服务问题

| 现象 | 排查 |
|---|---|
| 隐患识别 503 / 超时 | 在模型调用设置检查 VLLM URL、Model ID、组织/环境和掩码密钥；确认网络可达供应商 |
| LLM 问答返回 503 | 检查 LLM 是否启用、URL/Model ID/密钥是否完整；`GET /api/local/llm/status` 查看配置状态 |
| STT 识别失败 | 检查 STT 配置、ffmpeg 安装和音频文件头；Paraformer Realtime 必须可连接工作空间 WSS |
| TTS 提示缺少音色 | CosyVoice 3.5 不提供系统音色，在设置页填写克隆或设计生成的 voice ID |
| 模型密钥无法解密 | 确认 `MODEL_CONFIG_ENCRYPTION_KEY` 未变更；从备份恢复原加密密钥或重新保存四类 API Key |
| 密码登录失败 | 默认密码 `admin123`；确认已执行初始化脚本；bcrypt 哈希需 `passlib[bcrypt]` |
### 12.4 眼镜端/模拟器问题

| 现象 | 排查 |
|---|---|
| 模拟器无连接 | 打开 `/simulator/glasses-simulator.html`；`GET /api/simulator/status` 确认 `connected=true` |
| 指令下发无响应 | 确认 `action` 在支持列表内；检查 `CommandHandler.dispatch` 是否注册 |
| 眼镜端无法连接后端 | 确认 WiFi/5G 网络正常；检查后端服务是否运行；查看 `onConnected` 回调日志 |
| 拍照无回传 | 检查 WebSocket 是否断开；模拟器需主动上报 `photo_taken` 消息 |
| 企业版提示 SDK 初始化失败 | 检查 `ROKID_ENTERPRISE_APP_ID/SECRET`、glass/phone clientId、包名和签名是否与 Rokid 平台绑定 |
| 企业版拍照 `CAMERA_IN_USE` | 不要在 enterprise flavor 另行绑定 CameraX；项目已使用 Glass Media Service 独占相机 |
| 企业版 RTC 无法入会 | 检查 broker 返回的 room 是否一致、token 是否过期、`ROKID_RTC_URL` 与 SDK AppID 是否匹配 |
| 商业版手机扫描到但未连接 | 检查 BLE/经典蓝牙权限、目标设备固件、BLE 握手回调中的 socket UUID 和 classic MAC |

### 12.5 微信小程序问题

| 现象 | 排查 |
|---|---|
| `wx.request`/上传失败 | 检查开发者工具是否关闭“不校验合法域名”调试开关；正式环境确认 HTTPS 域名已配置并备案 |
| `wx.login` 后无法登录 | 检查 code 是否重复使用、AppID/AppSecret 是否匹配当前环境、账号是否已绑定 |
| 摄像头/麦克风无权限 | 检查隐私接口声明和用户授权；引导用户打开设置，不要循环弹授权 |
| 录音能上传但 STT 失败 | 检查录音格式、文件大小、ffmpeg、STT 模型配置与供应商 WSS 连通性 |
| 收不到来电 | 检查 WSS 合法域名、JWT、前后台状态；离线通知需用户完成订阅授权 |
| 无法进入 RTC 房间 | 检查组件/接口权限、RTC AppID、短期凭证、房间 ID 与用户 ID 是否一致 |
| 双方有画面无声音 | 检查麦克风权限、静音状态、音频路由和 RTC 网络质量事件 |

### 12.6 数据库问题

| 现象 | 排查 |
|---|---|
| 表未自动创建 | 确认 `init_db()` 中导入了所有模型模块；手动执行 `python scripts/init_default_users.py` |
| 字符集乱码 | 数据库与表必须 `utf8mb4`；连接串带 `?charset=utf8mb4` |
| 密码登录失败 | 默认密码 `admin123`；确认已执行初始化脚本；依赖清单中的 `bcrypt` 必须安装成功 |
